## 概要

ClassHub は現在、**四川師範大学の 2025 年入学・ソフトウェア工学 3 組**で利用されています。メンバーはクラスの最新情報の確認、ニュースの閲覧、活動への参加、リソースの共有、投稿、クラスの手続きができます。管理者も同じシステムで、コンテンツ、名簿、参加申請、提出記録を管理します。

React + TypeScript のフロントエンドと Node.js + Express + MongoDB のバックエンドで構成され、実際のアカウント、アクセス制御、コンテンツ管理、AI サービス、オブジェクトストレージ連携を備えています。現在はデプロイごとに 1 つのクラス名簿を使用し、マルチテナントや複数クラスの管理には対応していません。

ホームページ、サイトについてのページ、プライバシーページでは、製品に関する情報を公開しています。クラス用のページにはログインが、管理画面には管理者権限が必要です。ソースコードのリポジトリが公開されていても、クラスメンバーの情報や運用データが公開されるわけではありません。また、このプロジェクトは大学の公式組織を代表するものではありません。

**この README は、現在のリポジトリにある実装を説明しています。** デプロイ済みのバージョン、利用可能なコンテンツ、外部サービスの状況は異なる場合があります。コードが存在していても、すべての環境で設定やデプロイが完了しているとは限りません。

## 機能

### メンバー向け画面

| モジュール | 実装済みの機能 |
| --- | --- |
| ホームページ | 最新のお知らせ、活動、リソース、ニュースに加え、クラスの近況や活動の思い出を一部表示。全件は各セクションで閲覧可能 |
| お知らせと通知 | クラスのお知らせ、個人向け通知、未読状態の表示、通知の既読化 |
| ニュース | ニュース一覧、記事本文、リアクション、閲覧中の記事に関する AI との会話 |
| 活動 | 活動の段階、カレンダー、種類・年による絞り込み。参加申請、自分の承認状況の確認、キャンセル。活動報告、アルバム、過去の活動 |
| 学習リソース | リソースの一覧、詳細、リンク、ダウンロードの入口、利用記録 |
| クラスフィード | テキスト・画像の投稿、ディスカッション、リアクション、コンテンツの保存、既存のフォロー・公開範囲ルール |
| サイト内検索 | 共通の検索ダイアログを使い、現在のアカウントがアクセスできるコンテンツを検索 |
| 評価資料 | 受付期間中の ZIP 提出、提出状況の確認、期限前の再提出、自分のファイルのダウンロード |
| クラス会費 | 支払い用 QR コード、支払いのスクリーンショットと備考、管理者による確認状況 |
| ランダム指名 | 条件を満たす実際のメンバー全員から均等に選出し、アバターを使ったアルバムジャケットとレコードで表示。再抽選に対応 |
| アカウントと設定 | 学籍番号またはアカウント識別子によるログイン、パスワード変更、プロフィール、アバター、各種設定、保存済みコンテンツ |
| デフォルトアバター | アバター未登録の場合、安定したアカウント識別子に基づいてライブラリから割り当て。ページや端末が変わっても同じアバターを使用 |
| ウェブデスクトップペット | 任意で利用できるペット、スキン、インタラクション、アカウントに紐づく設定。[ペットのドキュメント](docs/classhub-pet.md)を参照 |

### 管理画面

| モジュール | 実装済みの機能 |
| --- | --- |
| ダッシュボード | 既存のクラスコンテンツと運用状況の概要 |
| 名簿とメンバー | 実際のクラス名簿のインポート、メンバー管理、アカウント権限の管理 |
| コンテンツ管理 | ニュース、リソース、お知らせ・通知、既存のアルバム記録 |
| 活動管理 | 下書きと公開、日時と定員、参加申請の審査と一括操作、未申請メンバー数、アルバム、活動報告、アーカイブ、非表示、復元 |
| 評価資料 | 受付期間、受付開始日時、実際の名簿に基づく提出済み・未提出メンバーの確認、記録の絞り込み、ダウンロード |
| クラス会費管理 | 支払い用 QR コードの設定、支払い証明の審査、手動の照合、入金確認 |
| AI アシスタント | テキスト・画像による支援、用途別の生成、編集可能な公開プレビュー、追加指示による修正、キャンセル、ストリーミング応答 |
| AI 日次ニュース | スケジュール・件数・カテゴリの設定、情報取得、検証、一括公開、実行状況、失敗理由、ジョブ履歴 |

### 操作と表示

- レスポンシブ対応のヘッダー、モバイル用下部ナビゲーション、中央揃えのフッター、共通のフォーム・ダイアログ・フィードバックコンポーネント。
- 初回訪問時のブランドプリローダー。現在のルート、初期表示範囲のフォント、表示中の画像の読み込みを待ちます。同一セッション内での再表示を避け、タイムアウトとキーボードによるスキップに対応しています。
- サイトについてのページには、滑らかなスクロール、独自の幾何学イラスト、円弧に沿って動く開発者カードがあります。このページにはサイトヘッダーを表示しません。
- 専用の 404 ページでは、ブランド表現、既存の検索機能、ローカルの宇宙飛行士イラストを再利用しています。
- アニメーションは `prefers-reduced-motion` を尊重します。モバイル端末とタッチ端末には、それぞれに適したレイアウトとスクロール動作を使用します。
- **現在のアプリケーションはライトテーマに固定されています。** 過去のダークスタイルやテーマ関連の依存関係があっても、ダークモード切り替えが利用できるわけではありません。

## ページと使い方

| ページ | パス | アクセス条件 |
| --- | --- | --- |
| ホームページ / サイトについて / プライバシー | `/`, `/about`, `/privacy` | 公開されている製品情報 |
| ログイン | `/auth` | クラスのアカウントでログイン |
| お知らせ / ニュース / 活動 | `/announcements`, `/news`, `/events` | ログイン済みのメンバー |
| リソース / クラスフィード | `/resources`, `/social` | ログイン済みのメンバー |
| 通知 / 保存済みコンテンツ / 設定 | `/notifications`, `/saved-posts`, `/settings` | 現在のアカウント |
| クラス機能 | `/functions` | ログイン済みのメンバー |
| 資料提出 / クラス会費 | `/quantification`, `/fees` | ログイン済みのアカウント。個々の操作はバックエンドで検証 |
| ランダム指名 | `/functions/random-call` | 現在、条件を満たすクラスメンバー |
| 管理画面 | `/admin` | バックエンドで検証された管理者 |
| 管理者用 AI / 日次ニュース | `/admin/ai`, `/admin/ai#daily-news` | 管理者 |

ニュース記事は `/article/:id` を使用し、互換性のために `/news/:id` も残しています。活動詳細は `/events/:id` を使用し、`/event/:id` も残しています。リソース詳細は `/resource/:id` です。ニュースの Q&A は記事ページの下部にあり、独立した公開チャットページではありません。

学生はクラス管理者が作成したアカウントでログインし、ナビゲーションから目的のセクションを開きます。管理者は実際の名簿を用意し、コンテンツを公開し、資料の受付期間を設定し、外部サービスを構成します。コンテンツが未公開の場合やサービスが利用できない場合は、状況に応じた空の表示やエラー表示になります。

## 技術とアーキテクチャ

| レイヤー | 技術と実装 |
| --- | --- |
| フロントエンド | React 18, TypeScript 5, Vite 5, React Router 6 |
| データとコンポーネント | TanStack React Query, Axios, Tailwind CSS, Radix UI, Lucide, React Markdown |
| アニメーション | GSAP 3.15, `@gsap/react`。サイトについてのページで必要に応じて ScrollTrigger / ScrollSmoother を読み込み |
| バックエンド | Node.js, Express 5, CommonJS。ルート、業務サービス、リポジトリで構成 |
| データベース | MongoDB, Mongoose 8 |
| 認証 | bcrypt によるパスワードのハッシュ化、JWT、データベースでのアカウント・管理者確認、`tokenVersion` によるセッションの失効 |
| AI | 共通の `DeepSeekAssistant`、SSE、制御されたウェブ検索、記事本文の抽出 |
| 画像とファイル | Multer, Sharp, Tencent Cloud COS / SCF、有効期間の短い署名、ブラウザーからの直接アップロード |
| 公開ページのレンダリング | ホームページ、サイトについて、プライバシーの実際の閲覧用 HTML をビルド時に生成し、実行時には React でインタラクションを提供 |
| デプロイ | ECS / Nginx / systemd。リポジトリには Vercel の設定も付属 |
| モバイル | レスポンシブウェブ、Web App Manifest、Capacitor 設定、Android プロジェクト |

```text
ブラウザー / React ページ
    |
    +-- 開発環境: Vite が /api と /uploads をプロキシ
    +-- 本番環境: Nginx リバースプロキシ / 独立した API オリジン
            |
            v
        Express API
            +-- JWT / アカウント / 権限の確認
            +-- Service / Repository -- MongoDB
            +-- DeepSeekAssistant -- DeepSeek
            |        +-- NewsAPI / 配信元の RSS / 制御されたウェブ情報取得
            +-- 保護されたストレージサービス -- SCF / COS
                                               ^
                       有効期間の短い認可によるブラウザーからのアップロード・ダウンロード
```

主なデータモデルは `User`、`EnrolledUser`、`News`、`Announcement`、`Event`、`ActivityMedia`、`Resource`、`SocialPost`、`Notification`、`Chat`、`AiSettings`、`DailyNewsJob` です。このほか、評価資料の受付期間、提出、アップロード、クラス会費の設定、支払い証明のモデルがあります。各機能は既存のユーザーと名簿を再利用し、別の学生データセットは管理しません。

## クイックスタート

### 1. 環境を準備する

- Git、Node.js、npm。既存の ECS デプロイでは **Node.js 22** を使用しており、ローカルでも同じメジャーバージョンを推奨します。リポジトリに `engines` 制約はありません。
- 接続可能な MongoDB インスタンス。既存のデプロイでは MongoDB 8 を使用しています。一部の操作はスタンドアロンの MongoDB にも対応しており、起動にレプリカセットのトランザクションは必須ではありません。
- AI とクラウドへのアップロードは任意の外部サービスです。未設定の場合は該当機能を利用できませんが、公開されている製品情報のページにはアクセスできます。

### 2. クローンして依存関係をインストールする

```bash
git clone https://github.com/Mason1035/uniclub-main.git
cd uniclub-main
npm ci
npm --prefix uniclub-backend ci
```

代わりに `npm run install-all` を使用すると、フロントエンドとバックエンドの両方で `npm install` を実行します。GSAP の依存関係は `vendor/` に同梱されたパッケージを使用するため、クローン、ビルド、デプロイの際はこのディレクトリを保持してください。

### 3. バックエンドを設定する

サンプルファイルをコピーします。

```bash
cp uniclub-backend/.env.example uniclub-backend/.env
```

Windows PowerShell の場合:

```powershell
Copy-Item uniclub-backend/.env.example uniclub-backend/.env
```

`uniclub-backend/.env` を編集し、少なくとも次の項目を設定します。

```dotenv
MONGODB_URI=mongodb://127.0.0.1:27017/uniclub
JWT_SECRET=replace_with_a_long_random_private_secret
PORT=5050
REQUIRE_ENROLLED_ROSTER=true
ALLOWED_EMAIL_DOMAINS=
```

接続文字列はローカル環境の例です。`JWT_SECRET` は必ず置き換えてください。サンプルにある NewsAPI / Gemini のプレースホルダーは有効なキーではなく、該当サービスを使わない場合は空にしてください。現在の DeepSeek の設定方法は後述しており、Gemini のキーは不要です。

`mongod` がインストール済みの場合は、別のターミナルで起動します。

```bash
npm run mongo
```

このスクリプトはデフォルトで `127.0.0.1:27017` にバインドし、データを `~/data/db` に保存します。MongoDB 自体はインストールしません。データベースサービスがすでに稼働している場合、この手順は不要です。ローカルの実行ファイル、データディレクトリ、ポートを変更するには、`MONGOD_BIN`、`MONGODB_DBPATH`、`MONGODB_PORT` を使用します。

### 4. フロントエンドとバックエンドを起動する

```bash
npm start
```

| サービス | デフォルトのアドレス |
| --- | --- |
| フロントエンド | <http://localhost:8081> |
| バックエンドのヘルスチェック | <http://localhost:5050/api/health> |
| サイトについて | <http://localhost:8081/about> |
| ログイン / 管理画面 | <http://localhost:8081/auth> / <http://localhost:8081/admin> |

バックエンドはデータベースに接続してからリクエストの待ち受けを開始します。初回利用時は、[管理者とクラス名簿を初期化](#accounts)してください。公開ホームページがメンバーや運用コンテンツを自動で作成することはありません。

`npm run backend` と `npm run frontend` を別々のターミナルで実行することもできます。標準の起動コマンドは Windows でも動作します。旧来の `start:win` / `stop:win` スクリプトは今もポート 5000 を前提にし、指定ポートのプロセスを終了するため、通常の起動方法としては推奨しません。

## 環境設定と外部サービス

### 設定の保存場所

| 設定 | 場所と用途 |
| --- | --- |
| バックエンドの接続、認証、サーバーのシークレット | `uniclub-backend/.env` または本番サーバーの保護された環境変数 |
| フロントエンドの開発用プロキシ | ルートの `.env.local` にある `VITE_API_PROXY_TARGET`。デフォルトは `http://localhost:5050` |
| 本番フロントエンドの API URL | ビルド時の `VITE_API_URL`。同一オリジンのリバースプロキシを使う場合は空にし、別ホストの場合は API オリジンを設定。`/api` は重ねて付けない |
| DeepSeek API キー | `/admin/ai` で設定し、`AiSettings` に暗号化して保存 |
| ストレージ設定 | 管理者用の評価資料ストレージ設定を非公開の設定ファイルに保存。`QUANTIFICATION_STORAGE_CONFIG_PATH` で保存先を変更可能 |

**`VITE_*` 変数はブラウザー向けのビルドに含まれるため、シークレットを入れてはいけません。** 古いルートの `.env.example` には `VITE_API_URL=http://localhost:5000` があります。これは現在の開発用プロキシのポートではなく、そのまま本番設定にコピーしないでください。

バックエンドのポートを変更する場合、起動前にルートの `.env.local` でプロキシ先を設定します。

```dotenv
VITE_API_PROXY_TARGET=http://localhost:5051
```

ルートの起動スクリプトは、この接続先に基づいてバックエンドのポートを決定します。`PORT` も設定する場合は、両者を一致させてください。本番環境の `VITE_API_URL` を変更した場合、フロントエンドの再ビルドが必要です。

### 任意のサービス

| サービス | 設定 | 未設定の場合 |
| --- | --- | --- |
| DeepSeek | `AI_SECRET_ENCRYPTION_KEY` を初期化してバックエンドを再起動し、管理画面で API キーを保存して接続をテスト | 管理者用 AI、ニュース Q&A、日次生成を利用不可 |
| ニュース検索 | 既存の `NEWS_API_KEY`。共通の情報取得レイヤーでは、指定された配信元の RSS フィードも使用可能 | RSS で結果を補完できるが、情報源、鮮度、ネットワークの制限に依存 |
| COS 直接接続アダプター | `OBJECT_STORAGE_PROVIDER=cos`, `COS_BUCKET`, `COS_REGION`, `COS_SECRET_ID`, `COS_SECRET_KEY` | 実際の資料アップロードを利用不可 |
| SCF + COS | 非公開バケット、リージョン、関数の呼び出し URL、対応するサーバー認証、管理者用ストレージ設定 | 該当するクラウドへのアップロード・ダウンロードを利用不可 |
| 活動メディア | 保護された SCF、`CLASSHUB_SCF_AUTH_SECRET`、活動用プレフィックスに限定した権限、CORS | 活動のオリジナル画像とサムネイルを正しく保存できない |
| 本番環境のリクエスト元 | 実際のドメインに合わせて `CORS_ORIGINS` と `BACKEND_URL` を設定 | クロスオリジンリクエストや生成されたリンクが失敗する可能性あり |
| 認証付き Cron | `CRON_SECRET` | 外部からの Cron リクエストを拒否 |

ストレージには、クラウドリソース、非公開アクセスのポリシー、CORS、永続ディレクトリも必要です。`npm start` は Tencent Cloud のバケット、関数、ロールを作成しません。現在の実装は COS に対応していますが、すぐに使える OSS アダプターは含まれていません。活動と評価資料はストレージ設定を共有し、オブジェクトのプレフィックスと業務上の権限を分けています。

[評価資料ガイド](docs/quantification.md)、[SCF の設定](uniclub-backend/cloud-functions/quantification/README.md)、[活動用 COS ガイド](docs/activity-v2/ACTIVITY_V2_COS.md)を参照してください。これらの文書には過去の実装記録も含まれるため、現在のソースコードと対象環境を確認して、実際に有効な設定を判断してください。

## 管理者とクラス名簿

### 管理者を初期化する

バックエンドの非公開環境に `ADMIN_EMAIL` と `ADMIN_PASSWORD` を設定します。必要に応じて `ADMIN_NAME` と `ADMIN_UNIQUE_ID` も設定し、リポジトリのルートから次を実行します。

```bash
npm run admin:create
```

- ログインにはメールアドレスではなく、**学籍番号 / アカウント識別子 `uniqueId`** を使用します。名簿に属さない単独の管理者のデフォルト識別子は `ADMIN-...` 形式です。
- 既存のアカウントが一致する場合、スクリプトはそのアカウントに管理者権限を付与することがあります。`ADMIN_UPDATE_PASSWORD=true` を明示的に設定しない限り、既存のパスワードは保持されます。
- 使用後は、常用する環境設定から初期化用の変数を削除してください。実際のパスワードを README、コマンド例、Git に記載しないでください。
- 既存の管理者のパスワードを変更するには、パスワードの入力を非表示にするターミナルコマンド `npm run admin:password -- admin@example.com` を使用します。このメールアドレスは例です。パスワードを変更すると、既存のセッションは無効になります。

### クラス名簿をインポートする

CSV、TSV、JSON に対応しています。学籍番号と氏名は必須で、メールアドレスは任意です。架空のメンバーを使った CSV の例:

```csv
uniqueId,name
202500001,Example Member A
202500002,Example Member B
```

まずインポート内容を確認してから、実際に書き込みます。

```bash
npm run roster:import -- ./roster.csv --dry-run
npm run roster:import -- ./roster.csv
```

`--dry-run` はアカウント、名簿のエントリ、インデックスを変更しません。実際のインポートでは、不足しているログインアカウントを作成します。**初期パスワードは学籍番号で、初回ログイン時に変更する必要があります。** 再インポートしても既存のパスワード、ロール、プロフィールは保持されます。実際の名簿を公開リポジトリにコミットしないでください。

デフォルトの登録ポリシーでは、メールアドレスと学籍番号が名簿に一致する必要があります。現在の主な運用方法は、アカウントをインポートし、学籍番号で直接ログインする方式です。`REQUIRE_ENROLLED_ROSTER=false` は登録時の名簿チェックを無効にしますが、名簿データの誤りに対する通常の回避策として使うべきではありません。

ランダム指名の対象は `User.isEnrolled` と `EnrolledUser.uniqueId` の共通部分であり、管理者ロールを理由に除外しません。名簿にいる学生管理者は対象に含まれ、名簿外の単独の管理者は含まれません。毎回、対象者全員から抽選するため、同じメンバーが続けて選ばれることがあります。ブラウザーの `crypto.getRandomValues()` と棄却サンプリングを使い、剰余演算による偏りを避けています。

## AI と日次ニュース

### 共通の AI サービス

管理者用アシスタント、ニュース Q&A、日次ニュースは、`DeepSeekAssistant`、データベース設定、API キーを共通で使用します。機能ごとに別の AI キーやクライアントを作成しません。現在のコードは `deepseek-flash` と `https://api.deepseek.com` を使用しており、モデル選択は共通サービスに集約されています。

暗号化用のマスターキーを初期化します。

```bash
npm --prefix uniclub-backend run ai:init-secret
```

バックエンドを再起動し、`/admin/ai` で DeepSeek API キーを入力して接続をテストします。マスターキーは 32 バイトの Base64 値で、API キーは AES-256-GCM で暗号化して保存します。データベースとマスターキーの両方をバックアップしてください。マスターキーを紛失または置換すると、保存済みの API キーを復号できなくなり、再入力が必要になります。

### 管理者向けコンテンツアシスタント

テキスト・画像入力、12 種類の用途、ストリーミング生成、Markdown 出力、追加指示による修正、キャンセルに対応しています。**リソースの説明、お知らせの下書き、ニュース記事、活動の紹介文**には、それぞれのセクション向けの公開プレビューがあります。編集、検証、確認を経て、既存の業務 API を通じて公開します。生成しただけで自動的に公開されることはありません。

### ニュース Q&A

- フロントエンドが送信するのは記事 ID と質問のみです。`GET/POST /api/chat/:articleId` はサーバー上で、信頼できる記事本文、記事の公開範囲、現在のユーザーの履歴を読み取ります。
- 要約、記事の論点、組織の抽出では記事自体を優先します。「なぜ」という質問、影響分析、比較などでは推論を有効にできます。
- 最新の状況、時事情報、その後の展開、明示的な調査依頼については、必要に応じて共通の検索を実行します。外部のウェブコンテンツは、システムへの指示ではなく、信頼されていない参考データとして扱います。
- 長い記事と会話履歴には、コンテキスト量の上限があります。SSE で応答を分割表示し、既存の Markdown レンダラーを使用します。外部情報源は、実際に取得したものに限ります。
- 検索に失敗した場合、モデルは記事の内容を使って回答できます。会話は既存の `Chat` モデルに保存し、ユーザーと記事ごとに分離します。質問の上限は 1,000 文字です。
- バックエンドのレート制限と同時実行保護が適用されます。ニュース Q&A のデフォルトは、ユーザーごとに 10 分間で 20 リクエストです。現在は単一プロセスのメモリ内での保護であり、分散型のクォータ管理ではありません。

### AI 日次ニュース

`/admin/ai#daily-news` で設定、状態、ジョブ履歴を管理します。デフォルトは北京時間の `19:00`、1 日 2 記事です。件数は 1〜5 記事に設定でき、人工知能、テクノロジー、ソフトウェア工学、科学、教育を扱います。

```text
定期チェック / 管理者が確認した実行
    -> NewsAPI + 配信元の RSS から情報を取得
    -> 鮮度、配信元、情報源を検証
    -> 話題の選定、情報源の閲覧、生成、事実確認
    -> 完成したバッチを公開待ちにする
    -> 成功時に表示するバッチを切り替え、手動作成の記事と過去のバッチ記録は保持
```

ジョブは過去 24 時間以内に公開された実際の情報源を使います。信頼できる情報源が不足した場合や検証に失敗した場合、架空の内容で補うことも、直近の成功したバッチを置き換えることもありません。古い AI ニュースはバッチ単位でアーカイブし、手動で作成したニュースは自動削除しません。

常駐するバックエンドプロセスは、`NODE_ENV=production` の場合にスケジュールされたジョブを確認します。開発環境での起動時には、有料 AI サービスを自動で呼び出しません。Vercel Cron は保護された `/api/cron/daily-news` エンドポイントを使用し、`CRON_SECRET` が必要です。また、設定した頻度と十分な実行時間に対応するプランが必要です。

バックエンドのディレクトリから手動診断を実行します。

```bash
cd uniclub-backend
node manual-curation.js --dry-run
```

**この `--dry-run` も実際のネットワークリクエストと有料 AI の呼び出しを行います。ニュースの保存だけを抑止します。** フラグを付けない場合、コマンドは公開を試みます。`--force` はその日のバッチを明示的に再生成します。旧来のキュレーションコマンドも現在は統合された日次ニュースの処理を使います。過去の、ダラスの午前 0 時に実行する Gemini タスクの設定は使用しないでください。

NewsAPI の無料 Developer プランでは取得記事に 24 時間の遅延があり、公式に開発とテストのみに限定され、ステージングと本番環境は対象外です。このプロバイダーを本番で使用するには、適切なプランが必要です。[NewsAPI の公式料金ページ](https://newsapi.org/pricing)を参照してください。RSS は情報源の補完に使えますが、ローカルでの成功は、サーバーのネットワーク、情報源のページ、すべての公開日時が正常に扱えることを保証しません。実装の詳細は[日次ニュースのドキュメント](uniclub-backend/README.daily-news.md)を参照してください。AI の出力と引用元を確認してください。費用はプロバイダーと実際の利用量に依存します。

## デプロイと運用

### フロントエンドの出力と HTTP ルート

`npm run build` は、次を含む `dist/` を生成します。

- `index.html`、`about.html`、`privacy.html`: 訪問者向けの実際のコンテンツ。
- `app.html`: ログイン、メンバー用ページ、管理画面のための非公開アプリケーションシェル。
- `404.html`: 不明なルート用のページ。
- `sitemap.xml`、`seo-routes.json`、`static/`、公開アセット。

不明な URL をすべて一律にホームページへ送らないでください。デプロイでは、公開ページ、非公開シェル、API プロキシ、実際の 404 応答を区別する必要があります。Canonical URL、robots ディレクティブ、JSON-LD、サイトマップの対象は、確認済みの公開製品情報ページのみです。

### ECS / Nginx / systemd

リポジトリには既存サーバー向けのリリース、バックアップ、ロールバック手順があります。[`deploy/ecs/README.md`](deploy/ecs/README.md)を参照してください。常駐する Node.js プロセス、MongoDB、Nginx を使い、現在必要なファイルベースの設定、アップロード、バックグラウンドジョブに対応しています。

SSH アクセス、対象ディレクトリ、環境設定を確認した後、保守担当者は次を実行できます。

```bash
bash deploy/ecs/push.sh
```

このコマンドはビルド、転送、サーバーのリリース切り替えを行います。**任意の新しいサーバーを 1 コマンドで構築するインストーラーではありません。** 実行前に対象を確認してください。

デプロイ時の注意点:

- バックエンドの環境ファイル、アップロード、非公開のストレージ設定はリリースディレクトリの外に置きます。保護されたバックアップに含め、Git やフロントエンドのバンドルには含めません。
- 公開 HTTPS は Nginx で配信します。バックエンドとデータベースは、デプロイ構成に応じてループバックまたはプライベートネットワークのインターフェースにバインドします。
- 実際の本番環境に合わせて `CORS_ORIGINS` を設定します。`TRUST_PROXY=loopback` は、それに対応するローカルリバースプロキシ構成でのみ使用します。
- SSE ストリーミング向けに十分なタイムアウトを設定します。逐次出力を妨げる中継側のキャッシュやバッファリングを避けます。
- リリース後は、ヘルスチェック、ログイン、公開 HTML、静的アセット、不明な URL の 404 応答、変更の影響を受ける機能を確認します。
- 少なくとも MongoDB、アップロード済みファイル、ストレージ設定、AI マスターキーをバックアップします。コードのロールバックではデータベースは巻き戻りません。

### Vercel とモバイルプロジェクト

`vercel.json` にはビルド、API、公開ページ、静的アセット、404、Cron の設定があります。ディスクへのアップロード、非公開設定への書き込み、プロセス内のレート制限、長時間実行する AI タスクには、プラットフォームに合わせた調整が必要です。既存のすべての機能をそのままサーバーレス環境へ移せるとは限りません。

リポジトリには Capacitor 設定と Android プロジェクトがあり、過去の `Uniclub` アプリケーション識別子が今も残っています。レスポンシブ対応のウェブサイトと Web App Manifest があっても、Android / iOS アプリが公開済みであることや、クラスデータをオフラインで利用できることを意味しません。

### データの更新

既存のスクリプトには、ペットのデフォルト設定、クラス会費の初期化、日次ニュース、Activity V2 向けのものがあります。保存場所は `uniclub-backend/migrations/` またはバックエンドのスクリプトディレクトリです。まずバックアップし、対象スクリプトとモジュールのドキュメントを読んでから実行の必要性を判断してください。ディレクトリ内のすべてを無条件に実行しないでください。

Activity V2 のマイグレーションはデフォルトで dry-run となり、明示的な `ACTIVITY_MIGRATION_MONGO_URI` を使用し、`--apply` を指定した場合にのみ書き込みます。リモートの対象には `--allow-remote` も必要です。クラス会費の初期化には `npm --prefix uniclub-backend run fees:init` を使用し、日次ニュースの互換性スクリプトは `uniclub-backend/migrations/20261006_daily_ai_news.js` です。これらの操作は通常のフロントエンドビルドとは別です。

## セキュリティ、プライバシー、既知の制限

| 項目 | 現在の動作と範囲 |
| --- | --- |
| 権限 | バックエンドで実際のアカウント、セッションバージョン、管理者状態を確認。フロントエンドのリンク非表示、robots ディレクティブ、noindex は、API やメディアの認可を代替しない |
| 旧来の API とメディア | 古い匿名エンドポイントやメディアリンクの一部には、別途監査が必要。すべての運用データが完全に非公開であるとは保証していない。[SEO/GEO 監査](docs/SEO_GEO_AUDIT.md)を参照 |
| クラスの範囲 | デプロイごとに 1 クラス。マルチテナント分離、全学管理、クラス切り替えは未対応 |
| クラス会費 | ユーザーごとに現在の記録を 1 件保持。スクリーンショットはデータベースに保存し、管理者が手動で照合。決済ゲートウェイ、入金の自動検出、OCR、返金、複数の会費期間にまたがる台帳は未対応 |
| 評価資料 | 最大 500 MiB の ZIP ファイル、マルチパートアップロード、同一セッション内の再試行に対応。ウイルススキャンはなし。未完了のアップロード中にページを再読み込みすると、通常はファイルの再選択が必要。ファイルハンドルを使った、ページ読み込みをまたぐ完全な再開機能はなし |
| 活動アルバム | JPEG / PNG / WebP、画像ごとに最大 10 MiB。WebP サムネイルを生成。サムネイルはメタデータを削除するが、オリジナルには EXIF が残る場合がある。新しいメディアには制御された署名付きアクセスを使用 |
| ランダム指名 | 名簿のエントリと条件を満たすアカウントの共通部分が対象。アカウント未作成の名簿エントリは除外。同じ人の再選出を許可し、重複なしモードは未対応 |
| AI | キーはサーバー側に保持。生成結果の確認が必要。検索、生成、クォータ、費用は外部サービスに依存 |
| 複数プロセス | AI のレート制限は現在プロセスのメモリ内で動作し、動的ストレージ設定のロックにも単一プロセスの制約がある。スケール前に評価が必要 |
| ファイルとバックアップ | COS オブジェクト、MongoDB データ、ローカルファイルは別々に管理。実際の名簿、支払いスクリーンショット、提出 ZIP、環境ファイル、バックアップを公開リポジトリに含めない |

利用者は[プライバシーとブラウザーストレージの説明](https://csrg3b.top/privacy)を確認できます。機能ドキュメントに過去の検証記録があっても、現在の本番環境ですべての問題が解決済みであることを意味しません。

アカウント、キー、メンバーのプライバシーに関わる問題では、攻撃手順の詳細、実データ、認証情報を公開 Issue に投稿しないでください。保守担当者との既存の非公開連絡手段で報告し、確認後に機密情報を除いた修正説明を公開してください。現在、リポジトリには独立した `SECURITY.md` がなく、対応期間の保証もありません。

## よくある質問

### localhost:8081 で接続が拒否されるのはなぜですか？

`npm start` が実行中であること、依存関係がインストールされていること、ポート 8081 が空いていることを確認してください。バックエンドの起動に失敗した場合は、ターミナルで MongoDB や環境設定のエラーを確認します。`ERR_CONNECTION_REFUSED` は対象ポートで接続可能なサービスがないことを意味し、ページの再読み込みでは解決しません。

### フロントエンドは正常に開くのに、API リクエストが失敗するのはなぜですか？

<http://localhost:5050/api/health> を確認し、`VITE_API_PROXY_TARGET` と実際のバックエンドのポートを照合してください。開発用プロキシと本番の `VITE_API_URL` は用途が異なります。本番で API を別ホストに配置する場合、正しい CORS 設定も必要です。データベースへの接続が切れていると、ヘルスエンドポイントは 503 を返すことがあります。

### ホームページにクラスの近況が表示されない、または管理画面を開けないのはなぜですか？

訪問者向けホームページは公開の製品情報を表示し、クラスコンテンツを読み取りません。ログイン後に表示される内容は、公開済みの記録によって決まります。管理画面の利用にはデータベース上の管理者権限が必要です。フロントエンドのボタンを変更したり、ロールのフィールドを偽装したりしても、権限は得られません。

### ニュース生成で `SEARCH_NO_RESULTS` や `INSUFFICIENT_SOURCES` が返るのはなぜですか？

ジョブ記録で、取得結果、独立した配信元、読み取り可能な記事本文、情報の鮮度を確認してください。有効なキーがあっても、十分な信頼できる情報源を確保できるとは限りません。無料 NewsAPI の遅延、RSS の障害、サーバーの接続状況が結果に影響することがあります。ジョブは鮮度の期間を広げたり、検証を無効にしたり、ニュースを捏造したりして不足分を埋めません。

### AI がローカルでは動くのに、デプロイ後に失敗するのはなぜですか？

対象環境の AI マスターキー、データベース設定、検索先への接続、情報源の抽出、プロキシのタイムアウト、ジョブの実行時間を照合してください。フロントエンドの設定が同じでも、サーバーのキー、ネットワーク、永続ディレクトリが同じとは限りません。ジョブのエラーコードで、失敗した段階を特定してください。

### アップロード時にストレージが利用不可、または CORS エラーと表示されるのはなぜですか？

管理者用ストレージ設定、非公開バケット、関数の認証、必要なプレフィックスに限定した権限、実際のサイトのオリジン、リクエストヘッダーを確認してください。活動メディアでは、保護されていない旧来の認証情報発行関数を再利用してはいけません。署名が期限切れになったら新しい署名を取得し、問題を回避するためにバケットを公開しないでください。

### ランダム指名の対象に入っていない人がいるのはなぜですか？

その人が現在の実際の名簿と、条件を満たすメンバーアカウントの両方に存在するか確認してください。条件を満たすアカウントがない名簿エントリは対象に入りません。管理者であること自体は除外理由になりませんが、名簿外の単独の管理者はランダム選出のクラスメンバーには含まれません。

### 複数クラスのデプロイ、ダークモードの有効化、モバイルアプリの公開をそのまま行えますか？

これらは完成済みの製品機能ではありません。複数クラスには明確なデータ分離の設計が必要で、現在のテーマはライトモードに固定されています。モバイルプロジェクトには、ブランド設定、署名、プラットフォーム設定、適切な検証がまだ必要です。

## 貢献と問題の報告

再現可能な問題は [Issues](https://github.com/Mason1035/uniclub-main/issues) で報告し、改善はプルリクエストで提出してください。

- 対象ページ、再現手順、期待する結果と実際の結果、端末環境を記載してください。スクリーンショットやログから機密情報を先に除去してください。
- 既存のルート、リクエストレイヤー、ユーザーモデル、コンポーネント、デザイントークンに従ってください。認証、AI、ストレージの重複したシステムを導入しないでください。
- メンバーデータ、権限、費用、クラウドリソース、マイグレーションに影響する変更では、その範囲、復旧時の動作、検証の限界を説明してください。
- 第三者のクレジット表記とライセンス通知を保持し、関係する変更と併せてドキュメントを更新してください。
- 変更内容に応じて関連するテスト、lint、型チェック、ビルドを実行してください。モック API の確認を本番環境での実動作検証として説明しないでください。
- 現在、独立した `CONTRIBUTING.md` や正式な `CHANGELOG.md` はありません。このセクションと該当モジュールのドキュメントに、貢献時の規約を記載しています。
