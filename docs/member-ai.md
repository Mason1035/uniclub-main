# ClassHub 成员 AI 模式

首页搜索按钮进入「AI 模式」。同一个弹窗保留「站内搜索」和「个人记忆」；原 Ctrl / Command + K 入口及登录校验继续生效。管理员在 `/admin/ai` 的「成员 AI 用量」查看统计，在 `/admin/feedback` 的「反馈收件箱」处理成员意见。

## 能力与数据范围

- 复用现有加密的 DeepSeek 配置、`deepseek-flash` 模型、流式客户端和图片验证，没有增加依赖或第二把 AI 密钥。
- 姓名从当前登录账号实时读取，只向模型提供姓名，不附带邮箱、学号、角色权限或成员名单。
- 站内 RAG 使用当前数据库内容，而不是把源码仓库发送给模型：按栏目与关键词查询、截取命中位置附近的正文、分段排序，再选取最多 6 个来源。每个集合最多 12 条候选，Mongo 执行上限 2 秒，完整站内上下文 JSON 不超过 12,000 字符。
- 覆盖当前有权查看的公告、新闻、学习资源、活动、往期活动、资源快捷链接和公开/班级动态。每次重新检查账号、业务权限和真实班级名单，隐藏、过期、未来内容和失效名单均有过滤。业务管理人员可检索允许读取的草稿。
- 资源检索覆盖标题、简介、分类、标签和附件文件名，**没有解析 PDF、Word、压缩包等附件正文，也没有自动读取资源外链正文**。界面来源可直达原内容，摘录明确标注范围。个人材料、支付凭证、私密/好友动态、他人记忆和服务器配置不进入知识上下文。
- 本期采用结构化查询与本地相关性排序，无额外嵌入服务、向量数据库或持久化的全站副本，因此内容修改后下一次检索直接读新数据。

## 联网与照片

联网由成员主动开启，使用 DeepSeek 官方固定端点 `POST /v1/tools/search`，沿用现有服务器密钥。搜索只发送当前问题的前 128 个 Unicode 字符，不附带个人记忆、站内摘录、照片、姓名或历史对话。最多保留 4 条去重、安全的来源和有限摘要；不在服务器任意抓取用户 URL。无结果和失败均如实提示，不声称完成联网核实。

照片每次最多 4 张，每张不超过 2 MiB，支持 JPEG、PNG、GIF、WebP。服务器通过真实图片解码、格式与尺寸校验后用于当前模型请求，不保存到上传目录或长期记忆。前端只临时保留 File 与预览 URL，关闭或移除后释放。

供应商协议参考：[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[图像理解](https://api-docs.deepseek.com/zh-cn/guides/vision/)、[网页搜索](https://api-docs.deepseek.com/zh-cn/guides/search/)。搜索按接口请求另外计量，不能把搜索次数当作 token 或人民币费用。

## 每人独立的记忆档案

`assistant_memories` 每个账号一份文档，内容使用现有服务器主密钥进行 AES-256-GCM 加密；所有操作均由 JWT 对应账号确定归属，不能提交另一个 userId 来访问。使用修订号比较更新防止多标签页覆盖。

成员可在「个人记忆」中新增、编辑、删除记忆，并决定是否在回答中使用；也可在对话中明确输入「请记住：内容」或「记住：内容」。只有当前问题明确匹配这类命令且没有附图时才本地保存，不调用模型，不产生 token 用量。普通提问、历史对话与检索材料不会触发保存。最多 30 条，每条 500 字，实际给模型的记忆上下文上限 2,000 字。聊天和照片不会自动写入记忆。成员可以导出自己的 `.md` 文件；持久化的权威副本位于数据库，不依赖单台服务器的用户文件路径。切换账号会清空前端对话并取消旧请求。

部署时沿用现有 `AI_SECRET_ENCRYPTION_KEY`，并纳入安全备份；更换该主密钥前需要迁移已有密文。替换 DeepSeek API Key 本身不改变该主密钥。

## AI 对话中的随机点名

成员可以直接输入「随机抽一个人」「随机点名」「随机抽取3名同学」「再抽一个」。后端只识别当前问题里的明确指令，再复用 `/api/users/random-call-members` 的同一名单服务：账号必须仍在真实班级名单中且已入班，参与池为当前名单与已入班账号的交集，班级内的管理员同样参与。每次重新检查名单，已移出班级的账号无法继续抽取。

采用 Node `crypto.randomInt` 和部分 Fisher–Yates 抽样，同一批次不重复；人数可为阿拉伯数字或常见中文数字，最多 50 位且不得超过当前实际人数。空名单、无权限和超过人数会明确提示，不编造名字、不重复填充。性别等未实现的筛选条件不会被静默忽略。

抽取不经过 DeepSeek、不消耗模型 token，不向模型发送完整名单，也不建立模型用量记录。对话的 JSON / SSE 结果附 `localAction: "random_call"`、真实结果及随机点名页链接。客户端不显示「用量未回传」提示。公告、历史对话、图片或记忆中的抽取语句不会触发动作；该动作没有给模型增加修改业务或访问账号的工具。

## 成员用量

`assistant_usage` 以服务器生成的请求 UUID 作为唯一记录键，包含账号、模型、请求状态、服务商实际返回的输入/输出/总 token 和联网次数，不保存问题、答案、图片或记忆内容。最终流式分块上的用量会被读取；重复分块不会重复累计。

- 新账本从成员 AI 模式启用后开始。此轮起，成员 AI、反馈助手、新闻问答、管理员手动生成、密钥测试、每日新闻手动运行及预览均按调用人的账号计入；服务器定时每日新闻任务仍属于系统作业。没有记录的更早历史调用无法补算。
- 请求次数包含通过配置/图片验证并建立账本后的请求，可能包括后续失败或取消。
- 只有可靠、非负整数且总数一致的服务商 usage 才作为已上报 token。中断或缺失回传标记为「用量待确认」，不能认定为消耗为零。
- 联网次数统计已确认返回的搜索请求，含无结果的请求；供应商失败或中断时实际收费可能未知，界面不估算费用。
- 管理员可按姓名/邮箱查询并分页，汇总数字随筛选变化；老师和班委无权读取成员用量。
- 每个账号（包括管理员）在滚动 24 小时内最多使用 **100,000 token**，不按午夜统一清零。实际消耗按服务商回传的输入 + 输出 token 统计；管理员表格同时显示该窗口的已用与可用额度。
- `assistant_quotas` 每人一份修订号文档，在每次实际模型 HTTP 调用前，以 Mongo CAS 原子预留保守输入上界与本次最大输出；不足时缩短最大输出或返回 `AI_QUOTA_EXCEEDED`（HTTP 429 / SSE error）。规划、重试、格式修复等额外调用各自预留，跨实例并发也不能共用同一份可用额度。不可通过客户端篡改额度或换 AI 入口绕过。
- 服务商回传可靠 usage 后按调用 ID 幂等结算，释放多余预留；预留量单独展示，不当作实际消耗。网络中断、取消或缺失 usage 的调用保留预留最多 24 小时，避免把未知账单当作零。启用限额时只导入旧账本最近 24 小时已回传的真实 token；旧请求缺失用量仅保留在账本的待确认统计中，不虚构整份额度预留。读取额度时会按修订号原子修复此前错误的旧预留，保留实际用量与新调用的真实预留。
- 达限时暂停所有人工模型调用；站内搜索、手动管理个人记忆与手动提交反馈继续可用。对话界面仅显示已用、上限和剩余额度，并在滚动窗口释放额度时重新获取。现有进程级并发/请求限制继续适用。以上不是费用余额或自动扣费功能。

## 反馈 / 意见

欢迎页第四个建议是「向开发者提供反馈 / 意见」，已有对话也可随时进入。反馈助手只使用当前反馈对话，帮助追问和整理问题、复现情况、期待效果、相关页面；不自动写入收件箱，不携带普通 AI 对话、照片或个人记忆。AI 回复仍消耗本人 24 小时额度。即使额度已用完或 AI 未配置，成员也能直接填写摘要。

提交前显示可编辑摘要，只有成员点击「确认提交给管理员」才会创建 `assistant_feedback` 记录。服务器从当前认证身份读取归属，只保存确认的字段及时间、处理状态，不保存反馈聊天全文；相同账号 + 提交 UUID 有唯一索引，网络重试和并发确认不会创建重复反馈。重复 UUID 若携带不同内容返回冲突。

仅当前管理员可在 `/admin/feedback` 阅读反馈、搜索、分页、按「未读 / 已读 / 已处理」筛选和变更状态，老师、班委和学生均无法访问该收件箱。收件箱是站内反馈功能，不会发送电子邮件或自动回复成员。

## 接口

全部位于 `/api/assistant`，均要求登录；个人身份只从服务器认证结果读取，响应使用 `private, no-store`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/status` | 是否已配置、模型、输入限制、记忆状态和当前额度 |
| GET | `/quota` | 本人滚动 24 小时已用 / 预留 / 剩余额度及最早恢复时间 |
| POST | `/chat` | multipart：prompt、history JSON、webSearch、images；SSE 或 JSON |
| GET | `/memory` | 本人记忆与开关 |
| PATCH | `/memory` | `{ enabled: boolean }` |
| POST | `/memory` | `{ text: string }` 新增 |
| PATCH / DELETE | `/memory/:id` | 编辑 / 删除本人条目 |
| GET | `/memory/export` | 本人 Markdown 记忆文件 |
| GET | `/usage` | 仅管理员；page、limit、search，含每人当前额度 |
| POST | `/feedback/chat` | JSON prompt、history、page；SSE 或 JSON，只整理草稿 |
| POST | `/feedback` | 本人确认的 title、description、expected、page、requestId |

管理员另有 `GET /api/admin/feedback` 和 `PATCH /api/admin/feedback/:id`，状态更新仅接受 `{ status }`。

SSE 沿用 `status`、`delta`、`result`、`error` 事件。问题上限 4,000 字；历史最多 10 条、16,000 字；输出最多 4,096 token。检索资料、图片、个人记忆和历史消息均作为不可信内容处理，不能作为改变权限、发布或修改账号的指令。模型没有写业务数据的工具。

## 验证

```sh
npm run test:assistant
npm run typecheck
npm run build
```

相关兼容回归包括后端 `search.test.js`、`newsChat.test.js`、`webSearch.test.js`、`startup.test.js` 和原有权限测试。独立临时 Mongo 数据库验证过记忆并发更新、加密、账号隔离、额度 CAS 并发与精确过期、实际调用账本与真实聚合，以及反馈确认落库、唯一索引幂等和管理员处理状态，未写入真实业务数据。真实 DeepSeek 验证仅使用合成姓名、纯色图片与公开网页检索。

浏览器当前受访问策略限制，尚未完成真实页面截图、控制台、真机触摸与性能验收；JSDOM 组件测试不能替代这些检查。

已知原有验证问题：管理员 AI 的旧 Meetup 活动发布用例仍返回 400（用例预期 201）；该问题在本次修改前也存在，本轮未改动活动校验来放宽约束。原联网测试的固定日期已过期，现改为相对当前时间的真实有效测试日期，并显式阻止该隔离用例访问真实 RSS，保留原有断言。
