# 未应用的成员 JSON API 访问保护提案

这是评审材料，当前运行代码没有应用 `seo-member-api.patch`。

## 为什么需要评审

前端 Layout 将新闻、活动、资源、公告、班级动态、往期活动和评论限制在登录状态，但部分对应 JSON GET 接口目前允许匿名读取。robots.txt 和 `noindex` 只影响抓取/索引，不是访问控制。

自动审批拒绝了包含鉴权、社交可见性、缓存和 Feed 调整的原始广泛补丁，理由是可能改变已有公开/成员业务行为。本提案收窄为一个全局 GET/HEAD 守卫；实施前仍需网站所有者确认，因为原先依赖匿名 API 的调用方会开始收到 401。

## 具体行为变化

- 新闻、活动、资源、公告、班级动态、往期活动这六类页面对应的 JSON 读取需要现有有效 JWT。
- 同时覆盖评论、精选/首页聚合、互动统计、用户 JSON，避免从聚合/评论接口绕过上述边界。
- 守卫复用已有 JWT 签名、账户存在检查和 tokenVersion 校验。有效成员和管理员继续进入原路由，原路由的状态/所有者/管理员权限检查仍负责最终返回。
- GET 和 HEAD 都检查；不更改任何 POST/PUT/PATCH/DELETE 的授权逻辑，OPTIONS 预检继续通过。
- 路径匹配沿用 Express 默认不区分大小写的路由规则，先归一化再检查，`/api/NEWS`、`/api/SOCIAL/Posts` 不能绕过守卫；图片例外同样不区分大小写。
- `/api/auth`、`/api/health`、已有带独立密钥保护的 `/api/cron` 不受新守卫影响。
- `<img>` 使用的 `/api/users/avatar/:id`、往期活动 poster/gallery 以及 `/uploads` 仍按现有传输方式获取，不能因此宣称这些媒体已成为私有资源。只保留 noindex 抓取指令。

## 测试和限制

补丁附带隔离测试，使用真实 JWT 验证、内存账户和本地测试服务器，检查匿名 JSON 请求在业务处理前返回 401、有效普通账户/管理员继续到达处理器、大小写路径、HEAD/预检/图片例外和命名空间边界。

这是访问守卫测试，不代表所有业务路由都应返回 200；例如普通成员进入管理员名单路由后仍应返回 403。应用补丁时还需要将现有 security.test.js 中匿名可读资源/活动详情的预期改为 401，并在首页、列表、详情、图片及管理员页面做最小回归。

**另有待处理风险：** 当前社交列表/评论分支与 `checkPostPrivacy` 的可见性规则不完全一致。全局 JWT 仅关闭匿名读取，无法代替每个帖子的作者/好友/私有权限检查。应单独评审最小的统一可见性修复；不得宣称本提案解决了所有私有帖子或成员媒体访问问题。
