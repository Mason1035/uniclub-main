## परियोजना परिचय

ClassHub वर्तमान में **सिचुआन नॉर्मल यूनिवर्सिटी की सॉफ़्टवेयर इंजीनियरिंग कक्षा 3, 2025 प्रवेश बैच** के लिए काम करता है। सदस्य कक्षा की सूचनाएँ देख सकते हैं, समाचार पढ़ सकते हैं, गतिविधियों में भाग ले सकते हैं, संसाधन साझा कर सकते हैं, पोस्ट लिख सकते हैं और कक्षा से जुड़े काम कर सकते हैं। प्रशासक इसी प्रणाली में सामग्री, सदस्य सूची, पंजीकरण और जमा किए गए रिकॉर्ड संभालते हैं।

परियोजना में React + TypeScript फ़्रंटएंड और Node.js + Express + MongoDB बैकएंड है। इसमें वास्तविक खाते, पहुँच नियंत्रण, सामग्री प्रबंधन, AI सेवाएँ और ऑब्जेक्ट स्टोरेज के साथ एकीकरण शामिल हैं। प्रत्येक डिप्लॉयमेंट में अभी एक ही कक्षा की सदस्य सूची उपयोग होती है; कई कक्षाओं या अलग-अलग संस्थाओं का प्रशासन समर्थित नहीं है।

मुखपृष्ठ, About और गोपनीयता पृष्ठ पर सार्वजनिक उत्पाद जानकारी उपलब्ध है। कक्षा के पृष्ठों के लिए लॉगिन और प्रशासन क्षेत्र के लिए प्रशासक की अनुमति आवश्यक है। कोड रिपॉज़िटरी सार्वजनिक होने से सदस्यों की निजी जानकारी या कामकाज का डेटा सार्वजनिक नहीं हो जाता। यह परियोजना विश्वविद्यालय के किसी आधिकारिक संगठन का प्रतिनिधित्व भी नहीं करती।

**यह README वर्तमान रिपॉज़िटरी में मौजूद कार्यान्वयन का वर्णन करता है।** डिप्लॉय किया गया संस्करण, उपलब्ध सामग्री और बाहरी सेवाओं की स्थिति अलग हो सकती है। कोड मौजूद होने का अर्थ यह नहीं कि हर वातावरण में उसकी कॉन्फ़िगरेशन और डिप्लॉयमेंट पूरी हो चुकी है।

### इंटरैक्शन और प्रस्तुति

- रिस्पॉन्सिव हेडर, मोबाइल पर नीचे नेविगेशन, केंद्रित फ़ुटर तथा साझा फ़ॉर्म, संवाद और प्रतिक्रिया घटक।
- पहली बार आने पर ब्रांड प्रीलोडर: वर्तमान रूट, पहले दिखने वाले फ़ॉन्ट और दिखाई देने वाले चित्रों का इंतज़ार करता है। उसी सत्र में दोबारा नहीं चलता; समयसीमा और कीबोर्ड से छोड़ने का विकल्प शामिल है।
- About पृष्ठ में स्मूथ स्क्रॉलिंग, मौलिक ज्यामितीय चित्र और चाप के साथ चलने वाले डेवलपर कार्ड हैं। इस पृष्ठ पर वेबसाइट का हेडर नहीं दिखता।
- अलग 404 पृष्ठ में ब्रांड, मौजूदा खोज और स्थानीय अंतरिक्ष यात्री चित्र का पुनः उपयोग होता है।
- एनिमेशन `prefers-reduced-motion` का सम्मान करते हैं। मोबाइल और टच उपकरणों पर उपयुक्त लेआउट और स्क्रॉल व्यवहार अपनाया जाता है।
- **वर्तमान ऐप में केवल लाइट थीम है।** पुराने डार्क स्टाइल या थीम से जुड़ी निर्भरताओं की मौजूदगी से डार्क मोड स्विच उपलब्ध होने का संकेत नहीं मिलता।

## पृष्ठ और उपयोग

| पृष्ठ | पथ | पहुँच |
| --- | --- | --- |
| मुखपृष्ठ / About / गोपनीयता | `/`, `/about`, `/privacy` | सार्वजनिक उत्पाद जानकारी |
| लॉगिन | `/auth` | कक्षा के खाते से प्रवेश |
| घोषणाएँ / समाचार / गतिविधियाँ | `/announcements`, `/news`, `/events` | लॉगिन किए हुए सदस्य |
| संसाधन / कक्षा फ़ीड | `/resources`, `/social` | लॉगिन किए हुए सदस्य |
| सूचनाएँ / सहेजी गई सामग्री / सेटिंग | `/notifications`, `/saved-posts`, `/settings` | वर्तमान खाता |
| कक्षा के कार्य | `/functions` | लॉगिन किए हुए सदस्य |
| सामग्री जमा करना / कक्षा निधि | `/quantification`, `/fees` | लॉगिन किए हुए खाते; हर कार्य की अनुमति बैकएंड जाँचता है |
| यादृच्छिक नाम चयन | `/functions/random-call` | कक्षा के वर्तमान पात्र सदस्य |
| प्रशासन क्षेत्र | `/admin` | बैकएंड द्वारा सत्यापित प्रशासक |
| प्रशासन AI / दैनिक समाचार | `/admin/ai`, `/admin/ai#daily-news` | प्रशासक |

समाचार लेखों का पथ `/article/:id` है; संगतता के लिए `/news/:id` भी बना हुआ है। गतिविधियों का विवरण `/events/:id` पर है और `/event/:id` भी समर्थित है। संसाधनों का विवरण `/resource/:id` पर मिलता है। समाचार प्रश्नोत्तर लेख के नीचे है; इसका अलग सार्वजनिक चैट पृष्ठ नहीं है।

छात्र प्रशासक द्वारा बनाए गए खातों से लॉगिन करके नेविगेशन से संबंधित अनुभाग खोलते हैं। प्रशासक पहले वास्तविक सदस्य सूची तैयार करते हैं, फिर सामग्री प्रकाशित करते हैं, संग्रह चरण खोलते हैं और बाहरी सेवाएँ कॉन्फ़िगर करते हैं। सामग्री प्रकाशित न होने या सेवा अनुपलब्ध होने पर उपयुक्त खाली स्थिति या त्रुटि संदेश दिखता है।

| डिप्लॉयमेंट | ECS / Nginx / systemd; रिपॉज़िटरी में Vercel कॉन्फ़िगरेशन भी है |
| मोबाइल | रिस्पॉन्सिव वेब, Web App Manifest, Capacitor कॉन्फ़िगरेशन और Android परियोजना |

```text
ब्राउज़र / React पृष्ठ
    |
    +-- विकास: Vite द्वारा /api और /uploads का प्रॉक्सी
    +-- उत्पादन: Nginx रिवर्स प्रॉक्सी / अलग API origin
            |
            v
        Express API
            +-- JWT / खाता / अनुमति जाँच
            +-- Service / Repository -- MongoDB
            +-- DeepSeekAssistant -- DeepSeek
            |        +-- NewsAPI / प्रकाशक RSS / नियंत्रित वेब सामग्री प्राप्त करना
            +-- सुरक्षित स्टोरेज सेवाएँ -- SCF / COS
                                            ^
                       सीमित अवधि की अनुमति से ब्राउज़र अपलोड या डाउनलोड
```

मुख्य डेटा मॉडल में `User`, `EnrolledUser`, `News`, `Announcement`, `Event`, `ActivityMedia`, `Resource`, `SocialPost`, `Notification`, `Chat`, `AiSettings` और `DailyNewsJob` शामिल हैं। इनके अलावा मूल्यांकन संग्रह चरण, जमा सामग्री, अपलोड, कक्षा निधि सेटिंग और भुगतान प्रमाणों के मॉडल हैं। सुविधाएँ मौजूदा उपयोगकर्ता और सदस्य सूची का पुनः उपयोग करती हैं; अलग छात्र डेटा नहीं रखतीं।

## शुरुआत करें

### 1. वातावरण तैयार करें

- Git, Node.js और npm। मौजूदा ECS डिप्लॉयमेंट में **Node.js 22** है; स्थानीय वातावरण में भी वही मुख्य संस्करण रखना उचित है। रिपॉज़िटरी में `engines` की अनिवार्य सीमा नहीं है।
- पहुँच योग्य MongoDB इंस्टेंस। मौजूदा डिप्लॉयमेंट में MongoDB 8 है। कुछ कार्य standalone MongoDB का समर्थन करते हैं; शुरू करने के लिए replica set transactions आवश्यक नहीं हैं।
- AI और क्लाउड अपलोड वैकल्पिक बाहरी सेवाएँ हैं। कॉन्फ़िगरेशन के बिना ये सुविधाएँ उपलब्ध नहीं होंगी, लेकिन सार्वजनिक परिचय पृष्ठ खुले रहेंगे।

### 2. कोड क्लोन करें और निर्भरताएँ स्थापित करें

```bash
git clone https://github.com/Mason1035/uniclub-main.git
cd uniclub-main
npm ci
npm --prefix uniclub-backend ci
```

वैकल्पिक रूप से `npm run install-all` फ़्रंटएंड और बैकएंड दोनों के लिए `npm install` चलाता है। GSAP निर्भरताएँ `vendor/` में शामिल पैकेजों से आती हैं; क्लोन, बिल्ड और डिप्लॉयमेंट के समय यह डायरेक्टरी साथ रखें।

### 3. बैकएंड कॉन्फ़िगर करें

उदाहरण फ़ाइल की कॉपी बनाएँ:

```bash
cp uniclub-backend/.env.example uniclub-backend/.env
```

Windows PowerShell:

```powershell
Copy-Item uniclub-backend/.env.example uniclub-backend/.env
```

`uniclub-backend/.env` में कम-से-कम ये मान भरें:

```dotenv
MONGODB_URI=mongodb://127.0.0.1:27017/uniclub
JWT_SECRET=replace_with_a_long_random_private_secret
PORT=5050
REQUIRE_ENROLLED_ROSTER=true
ALLOWED_EMAIL_DOMAINS=
```

कनेक्शन स्ट्रिंग स्थानीय उदाहरण है; `JWT_SECRET` बदलना आवश्यक है। उदाहरण फ़ाइल में NewsAPI / Gemini के placeholder वैध कुंजियाँ नहीं हैं। संबंधित सेवा का उपयोग न होने पर उन्हें खाली रखें। मौजूदा DeepSeek कॉन्फ़िगरेशन नीचे दिया गया है; इसके लिए Gemini कुंजी आवश्यक नहीं है।

अगर `mongod` पहले से स्थापित है, तो अलग टर्मिनल में चलाएँ:

```bash
npm run mongo
```

स्क्रिप्ट डिफ़ॉल्ट रूप से `127.0.0.1:27017` पर चलती है और डेटा `~/data/db` में रखती है; यह MongoDB स्थापित नहीं करती। डेटाबेस सेवा पहले से चल रही हो तो यह चरण छोड़ दें। स्थानीय executable, डेटा डायरेक्टरी या पोर्ट बदलने के लिए `MONGOD_BIN`, `MONGODB_DBPATH` और `MONGODB_PORT` उपयोग करें।

### 4. फ़्रंटएंड और बैकएंड शुरू करें

```bash
npm start
```

| सेवा | डिफ़ॉल्ट पता |
| --- | --- |
| फ़्रंटएंड | <http://localhost:8081> |
| बैकएंड स्वास्थ्य जाँच | <http://localhost:5050/api/health> |
| परिचय | <http://localhost:8081/about> |
| लॉगिन / प्रशासन | <http://localhost:8081/auth> / <http://localhost:8081/admin> |

डेटाबेस से जुड़ने के बाद ही बैकएंड पोर्ट पर सुनना शुरू करता है। पहली बार उपयोग से पहले [प्रशासक और कक्षा सूची तैयार करें](#accounts)। सार्वजनिक मुखपृष्ठ अपने आप सदस्य या कामकाज की सामग्री नहीं बनाता।

आप `npm run backend` और `npm run frontend` अलग टर्मिनल में भी चला सकते हैं। सामान्य स्टार्टअप कमांड Windows पर काम करती हैं। पुराने `start:win` / `stop:win` स्क्रिप्ट में अभी भी पोर्ट 5000 की धारणा और पोर्ट पर चलती प्रक्रियाएँ बंद करने का व्यवहार है; इन्हें डिफ़ॉल्ट स्टार्टअप तरीके के रूप में उपयोग करना उचित नहीं है।

## वातावरण और बाहरी सेवाएँ

### कॉन्फ़िगरेशन कहाँ रखें

| कॉन्फ़िगरेशन | स्थान और उद्देश्य |
| --- | --- |
| बैकएंड कनेक्शन, प्रमाणीकरण और सर्वर की गुप्त कुंजियाँ | `uniclub-backend/.env` या उत्पादन सर्वर के सुरक्षित वातावरण चर |
| फ़्रंटएंड विकास प्रॉक्सी | मुख्य डायरेक्टरी की `.env.local` में `VITE_API_PROXY_TARGET`; डिफ़ॉल्ट `http://localhost:5050` |
| उत्पादन फ़्रंटएंड का API URL | बिल्ड के समय `VITE_API_URL`; same-origin रिवर्स प्रॉक्सी के लिए खाली रखें, अलग सर्वर के लिए API origin भरें और `/api` दोबारा न जोड़ें |
| DeepSeek API कुंजी | `/admin/ai` में भरें; `AiSettings` में एन्क्रिप्ट करके रखी जाती है |
| स्टोरेज सेटिंग | प्रशासन क्षेत्र की मूल्यांकन सामग्री स्टोरेज सेटिंग; निजी कॉन्फ़िगरेशन फ़ाइल में सहेजी जाती है। स्थान बदलने के लिए `QUANTIFICATION_STORAGE_CONFIG_PATH` |

**`VITE_*` चर ब्राउज़र बिल्ड में शामिल होते हैं; इनमें कभी गुप्त कुंजियाँ न रखें।** मुख्य डायरेक्टरी की पुरानी `.env.example` में `VITE_API_URL=http://localhost:5000` है। यह मौजूदा विकास प्रॉक्सी का पोर्ट नहीं है और इसे सीधे उत्पादन कॉन्फ़िगरेशन में कॉपी नहीं करना चाहिए।

बैकएंड पोर्ट बदलने पर, शुरू करने से पहले मुख्य `.env.local` में प्रॉक्सी लक्ष्य सेट करें:

```dotenv
VITE_API_PROXY_TARGET=http://localhost:5051
```

मुख्य स्टार्टअप स्क्रिप्ट इस लक्ष्य से बैकएंड पोर्ट चुनती है। अलग से `PORT` भी सेट करें तो दोनों मान समान रखें। उत्पादन में `VITE_API_URL` बदलने के बाद फ़्रंटएंड दोबारा बिल्ड करना आवश्यक है।

## प्रशासक और कक्षा की सदस्य सूची

### प्रशासक तैयार करें

बैकएंड के निजी वातावरण में `ADMIN_EMAIL` और `ADMIN_PASSWORD` सेट करें। वैकल्पिक रूप से `ADMIN_NAME` और `ADMIN_UNIQUE_ID` भी सेट कर सकते हैं। फिर रिपॉज़िटरी की मुख्य डायरेक्टरी से चलाएँ:

```bash
npm run admin:create
```

- लॉगिन के लिए **छात्र आईडी / खाता पहचान `uniqueId`** उपयोग होती है, ईमेल नहीं। स्वतंत्र प्रशासक की डिफ़ॉल्ट पहचान `ADMIN-...` प्रारूप में होती है।
- मौजूदा खाता मिलने पर स्क्रिप्ट उसे प्रशासक की अनुमति दे सकती है। पुराना पासवर्ड तभी बदलता है जब `ADMIN_UPDATE_PASSWORD=true` स्पष्ट रूप से सेट किया जाए।
- शुरुआती सेटअप के बाद इन चरों को स्थायी वातावरण से हटा दें। वास्तविक पासवर्ड README, कमांड उदाहरण या Git में न रखें।
- मौजूदा प्रशासक का पासवर्ड बदलने के लिए छिपे पासवर्ड इनपुट वाला टर्मिनल कमांड चलाएँ: `npm run admin:password -- admin@example.com`। ईमेल केवल उदाहरण है। पासवर्ड बदलने से पुराने सत्र अमान्य हो जाते हैं।

### कक्षा की सदस्य सूची आयात करें

CSV, TSV और JSON समर्थित हैं। छात्र आईडी और नाम आवश्यक हैं; ईमेल वैकल्पिक है। काल्पनिक सदस्यों की CSV का उदाहरण:

```csv
uniqueId,name
202500001,Example Member A
202500002,Example Member B
```

पहले आयात जाँचें, फिर डेटा लिखें:

```bash
npm run roster:import -- ./roster.csv --dry-run
npm run roster:import -- ./roster.csv
```

`--dry-run` खाते, सदस्य सूची या इंडेक्स नहीं बदलता। वास्तविक आयात में अनुपस्थित लॉगिन खाते बनते हैं। **प्रारंभिक पासवर्ड छात्र आईडी होता है; पहली बार लॉगिन करने पर इसे बदलें।** दोबारा आयात करने पर मौजूदा पासवर्ड, भूमिकाएँ और प्रोफ़ाइल सुरक्षित रहती हैं। वास्तविक सदस्य सूची सार्वजनिक रिपॉज़िटरी में कभी न डालें।

डिफ़ॉल्ट पंजीकरण नीति में ईमेल और छात्र आईडी का सदस्य सूची से मिलान आवश्यक है। वर्तमान मुख्य प्रक्रिया खाते आयात करके छात्र आईडी से सीधे लॉगिन कराती है। `REQUIRE_ENROLLED_ROSTER=false` पंजीकरण के समय सूची की जाँच बंद कर देता है; गलत सूची डेटा ठीक करने के सामान्य तरीके के रूप में इसे उपयोग न करें।

यादृच्छिक नाम चयन में वे सदस्य शामिल होते हैं जो `User.isEnrolled` और `EnrolledUser.uniqueId` दोनों में मिलते हैं। प्रशासक की भूमिका होने के कारण किसी को नहीं हटाया जाता। सूची में मौजूद छात्र प्रशासक शामिल हैं; सूची से बाहर के स्वतंत्र प्रशासक शामिल नहीं हैं। प्रत्येक चयन पूरी पात्र सूची से होता है, इसलिए एक सदस्य लगातार दो बार भी चुना जा सकता है। ब्राउज़र `crypto.getRandomValues()` और rejection sampling से modulo bias से बचा जाता है।

## AI और दैनिक समाचार

### एक साझा AI सेवा

प्रशासन सहायक, समाचार प्रश्नोत्तर और दैनिक समाचार `DeepSeekAssistant`, समान डेटाबेस कॉन्फ़िगरेशन और समान कुंजी का पुनः उपयोग करते हैं। अलग AI कुंजियाँ या क्लाइंट नहीं बनते। वर्तमान कोड में `deepseek-flash` और `https://api.deepseek.com` उपयोग होते हैं; मॉडल चयन साझा सेवा में केंद्रित है।

एन्क्रिप्शन की मास्टर कुंजी बनाएँ:

```bash
npm --prefix uniclub-backend run ai:init-secret
```

बैकएंड दोबारा शुरू करें, `/admin/ai` में DeepSeek API कुंजी भरें और कनेक्शन जाँचें। मास्टर कुंजी 32 बाइट का Base64 मान है; API कुंजी AES-256-GCM एन्क्रिप्शन से रखी जाती है। डेटाबेस और मास्टर कुंजी दोनों का बैकअप रखें। मास्टर कुंजी खोने या बदलने पर सहेजी हुई API कुंजी डिक्रिप्ट नहीं हो सकती और उसे फिर से भरना पड़ता है।

### प्रशासन सामग्री सहायक

टेक्स्ट/चित्र इनपुट, 12 उपयोग परिस्थितियाँ, स्ट्रीमिंग निर्माण, Markdown परिणाम, आगे संशोधन और अनुरोध रोकना समर्थित हैं। **संसाधन विवरण, घोषणा के मसौदे, समाचार लेख और गतिविधि सामग्री** संबंधित अनुभागों के प्रकाशन पूर्वावलोकन देते हैं। संपादन, सत्यापन और पुष्टि के बाद मूल कार्य संबंधी API से सामग्री प्रकाशित होती है। सामग्री बन जाने से वह अपने आप प्रकाशित नहीं होती।

### समाचार प्रश्नोत्तर

- फ़्रंटएंड केवल लेख आईडी और प्रश्न भेजता है। `GET/POST /api/chat/:articleId` सर्वर पर विश्वसनीय लेख सामग्री, लेख की दृश्यता और वर्तमान उपयोगकर्ता का इतिहास पढ़ता है।
- सारांश, लेख के विचार और संगठनों के नाम जैसे प्रश्नों में लेख को प्राथमिकता मिलती है। “क्यों”, प्रभाव विश्लेषण और तुलना जैसे प्रश्न reasoning सक्रिय कर सकते हैं।
- नवीनतम स्थिति, वर्तमान घटनाओं, आगे के घटनाक्रम या स्पष्ट खोज अनुरोध पर आवश्यकता के अनुसार साझा खोज चलती है। बाहरी वेब सामग्री को अविश्वसनीय संदर्भ डेटा माना जाता है, सिस्टम निर्देश नहीं।
- लंबे लेखों और बातचीत के इतिहास के लिए संदर्भ सीमा है। SSE उत्तर के हिस्से दिखाता है और मौजूदा Markdown रेंडरर का उपयोग होता है। बाहरी स्रोत केवल वास्तविक खोज से आते हैं।
- खोज विफल होने पर मॉडल लेख के आधार पर उत्तर दे सकता है। बातचीत मौजूदा `Chat` मॉडल में रहती है और उपयोगकर्ता तथा लेख के अनुसार अलग होती है। प्रश्न की सीमा 1,000 अक्षर है।
- बैकएंड पर अनुरोध सीमा और समानांतर अनुरोध सुरक्षा लागू हैं। समाचार प्रश्नोत्तर की डिफ़ॉल्ट सीमा प्रति उपयोगकर्ता 10 मिनट में 20 अनुरोध है। यह अभी एक प्रक्रिया की मेमोरी में सुरक्षा है; वितरित कोटा प्रणाली नहीं है।

### AI दैनिक समाचार

`/admin/ai#daily-news` में सेटिंग, स्थिति और कार्य इतिहास देखें। डिफ़ॉल्ट समय बीजिंग समय के अनुसार `19:00` और प्रतिदिन दो लेख हैं। संख्या एक से पाँच लेख तक सेट की जा सकती है। श्रेणियाँ कृत्रिम बुद्धिमत्ता, तकनीक, सॉफ़्टवेयर इंजीनियरिंग, विज्ञान और शिक्षा हैं।

```text
निर्धारित जाँच / प्रशासक की पुष्टि से चलाना
    -> NewsAPI + प्रकाशक RSS खोज
    -> समय, प्रकाशक और स्रोत का सत्यापन
    -> विषय चयन, स्रोत पढ़ना, सामग्री बनाना और तथ्यों की समीक्षा
    -> पूरा बैच अस्थायी रूप से तैयार रखना
    -> सफलता पर दिखने वाला बैच बदलना; मैन्युअल लेख और पुराने बैच रिकॉर्ड रखना
```

यह कार्य पिछले 24 घंटों में प्रकाशित वास्तविक स्रोत उपयोग करता है। विश्वसनीय स्रोत कम हों या सत्यापन विफल हो तो गढ़ी हुई सामग्री से संख्या पूरी नहीं की जाती और पिछला सफल बैच नहीं बदला जाता। पुराने AI समाचार बैच के अनुसार संग्रहित होते हैं; हाथ से बनाए गए समाचार अपने आप नहीं हटते।

`NODE_ENV=production` में स्थायी बैकएंड प्रक्रिया निर्धारित कार्य जाँचती है। विकास वातावरण में शुरू करने पर भुगतान वाली AI सेवाएँ अपने आप नहीं चलतीं। Vercel Cron सुरक्षित `/api/cron/daily-news` endpoint उपयोग करता है। इसके लिए `CRON_SECRET`, तय आवृत्ति का समर्थन करने वाला प्लान और पर्याप्त निष्पादन समय चाहिए।

मैन्युअल निदान बैकएंड डायरेक्टरी से चलाएँ:

```bash
cd uniclub-backend
node manual-curation.js --dry-run
```

**यह `--dry-run` भी वास्तविक नेटवर्क अनुरोध और भुगतान वाली AI कॉल करता है; केवल समाचार सहेजना रोकता है।** फ़्लैग हटाने पर प्रकाशन का प्रयास होता है। `--force` उसी दिन का बैच स्पष्ट रूप से दोबारा बनाता है। पुराने समाचार संकलन कमांड अब एकीकृत दैनिक समाचार प्रक्रिया उपयोग करते हैं; पुराने Dallas आधी रात वाले Gemini कार्य के निर्देशों से उन्हें कॉन्फ़िगर न करें।

NewsAPI का मुफ़्त Developer प्लान लेखों को 24 घंटे की देरी से देता है और आधिकारिक रूप से केवल विकास और परीक्षण के लिए है; staging और production इसके अंतर्गत नहीं आते। उत्पादन में इस सेवा के लिए उपयुक्त प्लान चाहिए। [NewsAPI की आधिकारिक मूल्य जानकारी](https://newsapi.org/pricing) देखें। RSS अतिरिक्त स्रोत दे सकती है, लेकिन स्थानीय सफलता से सर्वर नेटवर्क, स्रोत पृष्ठ या हर तारीख पर सफलता की गारंटी नहीं मिलती। कार्यान्वयन के लिए [दैनिक समाचार दस्तावेज़](uniclub-backend/README.daily-news.md) देखें। AI परिणाम और संदर्भ सत्यापित करें; खर्च सेवा प्रदाता और वास्तविक उपयोग पर निर्भर है।

## विकास, बिल्ड और जाँच

### सामान्य कमांड

ये कमांड रिपॉज़िटरी की मुख्य डायरेक्टरी से चलाएँ:

| कमांड | उद्देश्य |
| --- | --- |
| `npm start` / `npm run dev` | फ़्रंटएंड और बैकएंड साथ शुरू करना |
| `npm run frontend` / `npm run backend` | केवल एक हिस्सा शुरू करना |
| `npm run mongo` | पहले से स्थापित स्थानीय MongoDB शुरू करना |
| `npm run typecheck` | फ़्रंटएंड और Vite कॉन्फ़िगरेशन की TypeScript जाँच |
| `npm run lint` | मौजूदा ESLint कॉन्फ़िगरेशन से स्रोत की जाँच |
| `npm run build` | टाइप जाँच, Vite बिल्ड और सार्वजनिक SEO HTML बनाना |
| `npm run preview` | `dist/` का पूर्वावलोकन; बैकएंड या डेटाबेस शुरू नहीं करता |
| `npm test` | बैकएंड और पेट परीक्षण; हर विशेष फ़्रंटएंड स्क्रिप्ट शामिल नहीं है |
| `npm --prefix uniclub-backend run test:ai` | प्रशासन AI परीक्षण |
| `npm run test:seo` | सार्वजनिक पृष्ठ और डिप्लॉयमेंट रूट जाँच; पहले बिल्ड आवश्यक है |
| `npm run test:pet` | पेट परीक्षण |
| `npm run admin:create` / `npm run roster:import -- ...` | प्रशासक और सदस्य सूची तैयार करना; दिए गए विकल्पों के अनुसार डेटाबेस में लिखता है |
| `npm run curate:news` | मैन्युअल दैनिक समाचार कार्य; भुगतान वाली सेवाएँ चला सकता है और समाचार लिख सकता है |
| `npm run daily-curator` | अलग शेड्यूलर प्रक्रिया; उत्पादन की मुख्य प्रक्रिया में शेड्यूलर चल रहा हो तो सामान्यतः इसे अलग से शुरू करना आवश्यक नहीं है |

बदलाव के अनुसार मौजूदा संबंधित जाँचें चुनें:

```bash
node scripts/test-news-chat.mjs
node scripts/test-ai-preview.mjs
node scripts/test-daily-news-ui.mjs
node scripts/test-activity-frontend.mjs
node scripts/test-random-call.mjs
node scripts/test-default-avatars.mjs
node scripts/test-preloader.mjs
node scripts/test-request-sharing.mjs
node scripts/test-not-found.mjs
```

कुछ बैकएंड एकीकरण जाँचों के लिए MongoDB या अलग परीक्षण वातावरण चाहिए। Nginx उपलब्ध न होने पर SEO serving जाँच में वास्तविक Nginx प्रतिक्रिया परीक्षण छोड़ दिए जाते हैं। परीक्षण पास होने से बाहरी AI सेवाएँ, क्लाउड अनुमतियाँ, वास्तविक उपकरणों के ब्राउज़र या उत्पादन वातावरण सत्यापित नहीं होते। सामान्य बदलावों में सीधे संबंधित जाँचें और आवश्यक बिल्ड चलाएँ; हर बार पूरी वेबसाइट का regression परीक्षण आवश्यक नहीं है।

## डिप्लॉयमेंट और संचालन

### फ़्रंटएंड बिल्ड और HTTP रूट

`npm run build` से `dist/` बनता है, जिसमें शामिल हैं:

- `index.html`, `about.html`, `privacy.html`: आगंतुकों के लिए वास्तविक सामग्री।
- `app.html`: लॉगिन, सदस्य पृष्ठों और प्रशासन के लिए निजी ऐप का ढाँचा।
- `404.html`: अज्ञात रूट का पृष्ठ।
- `sitemap.xml`, `seo-routes.json`, `static/` और सार्वजनिक संसाधन।

हर अज्ञात URL को बिना जाँच मुखपृष्ठ पर न भेजें। डिप्लॉयमेंट में सार्वजनिक पृष्ठ, निजी ऐप ढाँचा, API प्रॉक्सी और वास्तविक 404 प्रतिक्रियाएँ अलग रखनी चाहिए। Canonical URL, robots निर्देश, JSON-LD और sitemap केवल समीक्षा किए गए सार्वजनिक परिचय पृष्ठों को कवर करते हैं।

### ECS / Nginx / systemd

मौजूदा सर्वर के रिलीज़, बैकअप और rollback प्रक्रियाएँ रिपॉज़िटरी में हैं; [`deploy/ecs/README.md`](deploy/ecs/README.md) देखें। इसमें स्थायी Node.js प्रक्रिया, MongoDB और Nginx उपयोग होते हैं, जो वर्तमान फ़ाइल-आधारित कॉन्फ़िगरेशन, अपलोड और पृष्ठभूमि कार्यों की ज़रूरतों के अनुरूप हैं।

SSH पहुँच, लक्ष्य डायरेक्टरी और वातावरण कॉन्फ़िगरेशन की जाँच के बाद रखरखावकर्ता यह चला सकते हैं:

```bash
bash deploy/ecs/push.sh
```

यह कमांड बिल्ड करता है, फ़ाइलें भेजता है और सर्वर का रिलीज़ बदलता है। **यह किसी भी नए सर्वर के लिए एक-कमांड इंस्टॉलर नहीं है।** चलाने से पहले लक्ष्य की पुष्टि करें।

डिप्लॉयमेंट में ध्यान रखें:

- बैकएंड वातावरण फ़ाइलें, अपलोड और निजी स्टोरेज कॉन्फ़िगरेशन रिलीज़ डायरेक्टरी से अलग रखें। इन्हें सुरक्षित बैकअप में शामिल करें, Git या फ़्रंटएंड बंडल में नहीं।
- सार्वजनिक HTTPS Nginx से दें। डिप्लॉयमेंट संरचना के अनुसार बैकएंड और डेटाबेस को loopback या निजी नेटवर्क इंटरफ़ेस पर बाँधें।
- वास्तविक उत्पादन `CORS_ORIGINS` कॉन्फ़िगर करें। `TRUST_PROXY=loopback` केवल संबंधित स्थानीय रिवर्स प्रॉक्सी संरचना में उपयोग करें।
- SSE स्ट्रीमिंग के लिए प्रॉक्सी और पर्याप्त timeout सेट करें। बीच की caching या buffering से क्रमिक उत्तर रुकने न दें।
- रिलीज़ के बाद स्वास्थ्य जाँच, लॉगिन, सार्वजनिक HTML, स्थिर संसाधन, अज्ञात URL की 404 प्रतिक्रिया और बदली हुई सुविधाएँ जाँचें।
- कम-से-कम MongoDB, अपलोड फ़ाइलें, स्टोरेज सेटिंग और AI मास्टर कुंजी का बैकअप रखें। कोड rollback से डेटाबेस rollback नहीं होता।

### Vercel और मोबाइल परियोजनाएँ

`vercel.json` में बिल्ड, API, सार्वजनिक पृष्ठ, स्थिर संसाधन, 404 और Cron कॉन्फ़िगरेशन हैं। डिस्क अपलोड, निजी कॉन्फ़िगरेशन लिखना, प्रक्रिया के भीतर अनुरोध सीमाएँ और लंबे AI कार्यों को प्लेटफ़ॉर्म के अनुसार अनुकूलित करना पड़ता है। सभी मौजूदा सुविधाएँ बिना बदलाव serverless वातावरण में चलेंगी, ऐसा न मानें।

रिपॉज़िटरी में Capacitor कॉन्फ़िगरेशन और Android परियोजना हैं, जिनमें पुराने `Uniclub` ऐप पहचानकर्ता अभी मौजूद हैं। रिस्पॉन्सिव वेबसाइट और Web App Manifest से यह निष्कर्ष नहीं निकलता कि Android/iOS ऐप प्रकाशित हैं या कक्षा का डेटा ऑफ़लाइन उपलब्ध है।

### डेटा उन्नयन

मौजूदा स्क्रिप्ट पेट की डिफ़ॉल्ट प्राथमिकताओं, कक्षा निधि की शुरुआती सेटिंग, दैनिक समाचार और Activity V2 को कवर करती हैं। वे `uniclub-backend/migrations/` या बैकएंड scripts में हैं। पहले बैकअप लें, लक्ष्य स्क्रिप्ट और मॉड्यूल दस्तावेज़ पढ़ें, फिर तय करें कि उसे चलाना है या नहीं। पूरी डायरेक्टरी बिना समीक्षा न चलाएँ।

Activity V2 migration डिफ़ॉल्ट रूप से dry-run है। इसमें स्पष्ट `ACTIVITY_MIGRATION_MONGO_URI` चाहिए और केवल `--apply` से डेटा लिखा जाता है। दूरस्थ लक्ष्य के लिए `--allow-remote` भी चाहिए। कक्षा निधि की शुरुआती सेटिंग के लिए `npm --prefix uniclub-backend run fees:init` है। दैनिक समाचार की संगतता स्क्रिप्ट `uniclub-backend/migrations/20261006_daily_ai_news.js` है। ये कार्य सामान्य फ़्रंटएंड बिल्ड से अलग हैं।

## सामान्य प्रश्न

### localhost:8081 कनेक्शन क्यों अस्वीकार करता है?

जाँचें कि `npm start` चल रहा है, निर्भरताएँ स्थापित हैं और पोर्ट 8081 खाली है। बैकएंड शुरू न हो तो टर्मिनल में MongoDB और वातावरण कॉन्फ़िगरेशन की त्रुटियाँ देखें। `ERR_CONNECTION_REFUSED` का अर्थ है कि लक्ष्य पोर्ट पर कोई सेवा उपलब्ध नहीं है; पृष्ठ refresh करने से यह ठीक नहीं होगा।

### फ़्रंटएंड खुलने के बावजूद API अनुरोध क्यों विफल होते हैं?

<http://localhost:5050/api/health> जाँचें, फिर `VITE_API_PROXY_TARGET` का वास्तविक बैकएंड पोर्ट से मिलान करें। विकास प्रॉक्सी और उत्पादन `VITE_API_URL` के उद्देश्य अलग हैं। अलग उत्पादन API सर्वर के लिए सही CORS भी चाहिए। डेटाबेस से कनेक्शन टूटने पर स्वास्थ्य endpoint 503 दे सकता है।

### मुखपृष्ठ पर कक्षा की सामग्री क्यों नहीं दिखती या प्रशासन क्षेत्र क्यों नहीं खुलता?

आगंतुक मुखपृष्ठ सार्वजनिक उत्पाद जानकारी दिखाता है और कक्षा की सामग्री नहीं पढ़ता। लॉगिन के बाद उपलब्ध सामग्री प्रकाशित रिकॉर्ड पर निर्भर है। प्रशासन के लिए डेटाबेस में प्रशासक की अनुमति चाहिए। फ़्रंटएंड बटन बदलने या भूमिका का नकली मान भेजने से अनुमति नहीं मिलती।

### समाचार निर्माण में `SEARCH_NO_RESULTS` या `INSUFFICIENT_SOURCES` क्यों आता है?

कार्य रिकॉर्ड में खोज परिणाम, स्वतंत्र प्रकाशक, पढ़े जा सकने वाले लेख और प्रकाशन समय देखें। वैध कुंजी से पर्याप्त विश्वसनीय स्रोतों की गारंटी नहीं मिलती। मुफ़्त NewsAPI की देरी, RSS विफलता या सर्वर कनेक्शन परिणाम प्रभावित कर सकते हैं। कार्य समय सीमा बढ़ाकर, सत्यापन बंद करके या समाचार गढ़कर कमी पूरी नहीं करता।

### AI स्थानीय वातावरण में चलता है लेकिन डिप्लॉयमेंट के बाद क्यों विफल होता है?

लक्ष्य वातावरण की AI मास्टर कुंजी, डेटाबेस सेटिंग, खोज कनेक्शन, स्रोत पढ़ने की क्षमता, प्रॉक्सी timeout और कार्य अवधि जाँचें। समान फ़्रंटएंड सेटिंग से सर्वर की कुंजियाँ, नेटवर्क और स्थायी डायरेक्टरी समान नहीं हो जाते। विफल चरण पहचानने के लिए कार्य के error code देखें।

### अपलोड में स्टोरेज अनुपलब्ध या CORS त्रुटि क्यों आती है?

प्रशासन स्टोरेज सेटिंग, निजी बकेट, फ़ंक्शन प्रमाणीकरण, आवश्यक पथ तक सीमित अनुमतियाँ, वास्तविक site origin और अनुरोध headers जाँचें। गतिविधि मीडिया के लिए पुराना असुरक्षित credential फ़ंक्शन दोबारा उपयोग न करें। हस्ताक्षर की अवधि समाप्त हो तो नया हस्ताक्षर लें; समस्या से बचने के लिए बकेट सार्वजनिक न बनाएँ।

### यादृच्छिक नाम चयन में कोई सदस्य क्यों नहीं है?

जाँचें कि वह वर्तमान वास्तविक सदस्य सूची और पात्र सदस्य खातों दोनों में मौजूद है। बिना पात्र खाते की सूची प्रविष्टियाँ चयन में शामिल नहीं होतीं। प्रशासक की भूमिका अपने आप किसी को बाहर नहीं करती, लेकिन सूची से बाहर का स्वतंत्र प्रशासक कक्षा के नाम चयन में सदस्य नहीं है।

### क्या सीधे कई कक्षाएँ, डार्क मोड या मोबाइल ऐप शुरू कर सकते हैं?

ये अभी पूरी हुई उत्पाद क्षमताएँ नहीं हैं। कई कक्षाओं के लिए स्पष्ट डेटा पृथक्करण डिज़ाइन चाहिए। वर्तमान थीम केवल लाइट है। मोबाइल परियोजना में ब्रांडिंग, signing, प्लेटफ़ॉर्म कॉन्फ़िगरेशन और उचित जाँच अभी आवश्यक हैं।

## योगदान और समस्या रिपोर्ट

दोहराई जा सकने वाली समस्याएँ [Issues](https://github.com/Mason1035/uniclub-main/issues) में बताएँ या सुधार के लिए Pull Request भेजें।

- पृष्ठ, समस्या दोहराने के चरण, अपेक्षित और वास्तविक परिणाम तथा उपकरण वातावरण लिखें। स्क्रीनशॉट और लॉग से पहले संवेदनशील जानकारी हटाएँ।
- मौजूदा रूट, अनुरोध परत, उपयोगकर्ता मॉडल, घटक और डिज़ाइन tokens अपनाएँ। प्रमाणीकरण, AI या स्टोरेज की दूसरी समान प्रणाली न बनाएँ।
- सदस्य डेटा, अनुमतियों, खर्च, क्लाउड संसाधन या migration से जुड़े बदलावों का दायरा, विफलता से पुनर्प्राप्ति और जाँच की सीमाएँ स्पष्ट करें।
- तीसरे पक्ष के स्रोत और लाइसेंस नोटिस बनाए रखें। संबंधित बदलाव के साथ दस्तावेज़ अपडेट करें।
- बदलाव के अनुसार संबंधित परीक्षण, lint, typecheck या build चलाएँ। mock API जाँच को वास्तविक उत्पादन सत्यापन न बताएँ।
- अभी अलग `CONTRIBUTING.md` या औपचारिक `CHANGELOG.md` नहीं है। योगदान नियम इस अनुभाग और संबंधित मॉड्यूल दस्तावेज़ों में हैं।
