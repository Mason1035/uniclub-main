## О проекте

ClassHub сейчас обслуживает **группу № 3 по программной инженерии набора 2025 года в Sichuan Normal University**. Участники могут находить сообщения группы, читать новости, участвовать в мероприятиях, делиться материалами, публиковать записи и решать организационные задачи. Администраторы в той же системе управляют контентом, списком участников, регистрациями и поданными материалами.

Проект использует фронтенд на React + TypeScript и бэкенд на Node.js + Express + MongoDB. В нём есть реальные учётные записи, контроль доступа, управление контентом, сервисы ИИ и интеграция с объектным хранилищем. Каждое развёртывание пока использует список одной учебной группы; управление несколькими группами и изоляция нескольких организаций не реализованы.

Главная страница, About и страница конфиденциальности содержат общедоступную информацию о продукте. Страницы группы требуют входа, а панель управления — прав администратора. Публичный репозиторий кода не делает сведения об участниках и рабочие данные общедоступными. Проект не представляет официальную организацию университета.

**Этот README описывает реализацию в текущем репозитории.** Развёрнутая версия, доступный контент и состояние внешних сервисов могут отличаться. Наличие кода не означает, что соответствующая возможность настроена и опубликована в каждой среде.

### Интерфейс и представление

- Адаптивная шапка, нижняя навигация на мобильных устройствах, центрированный подвал и общие компоненты форм, диалогов и сообщений.
- Брендовый прелоадер при первом посещении: ждёт текущий маршрут, шрифты первого экрана и видимые изображения; не повторяется в том же сеансе, предусматривает тайм-аут и пропуск с клавиатуры.
- На странице About есть плавная прокрутка, оригинальные геометрические иллюстрации и карточки разработчиков, движущиеся по дуге. Шапка сайта на этой странице не отображается.
- Отдельная страница 404 использует фирменный стиль, существующий поиск и локальную иллюстрацию астронавта.
- Анимации учитывают `prefers-reduced-motion`; мобильные и сенсорные устройства используют соответствующие раскладки и способы прокрутки.
- **Текущее приложение использует только светлую тему.** Старые тёмные стили или связанные с темами зависимости не означают, что переключение тёмного режима доступно.

## Страницы и использование

| Страница | Путь | Доступ |
| --- | --- | --- |
| Главная / About / Конфиденциальность | `/`, `/about`, `/privacy` | Общедоступная информация о продукте |
| Вход | `/auth` | Вход с учётной записью группы |
| Объявления / Новости / Мероприятия | `/announcements`, `/news`, `/events` | Авторизованные участники |
| Ресурсы / Лента группы | `/resources`, `/social` | Авторизованные участники |
| Уведомления / Сохранённое / Настройки | `/notifications`, `/saved-posts`, `/settings` | Текущий аккаунт |
| Функции группы | `/functions` | Авторизованные участники |
| Подача материалов / Взносы | `/quantification`, `/fees` | Авторизованные аккаунты; отдельные действия проверяет бэкенд |
| Случайный выбор участника | `/functions/random-call` | Текущие подходящие участники группы |
| Панель управления | `/admin` | Администраторы, проверенные бэкендом |
| ИИ администратора / Ежедневные новости | `/admin/ai`, `/admin/ai#daily-news` | Администраторы |

Статьи открываются по `/article/:id`; для совместимости сохранён `/news/:id`. Страница мероприятия использует `/events/:id`, также поддерживается `/event/:id`. Ресурсы открываются по `/resource/:id`. Вопросы к ИИ находятся внизу страницы статьи, отдельного публичного чата для них нет.

Студенты входят с аккаунтами, созданными администратором группы, и открывают нужный раздел через навигацию. Администраторы готовят реальный список участников, публикуют контент, открывают периоды сбора и настраивают внешние сервисы. Если контент ещё не опубликован или сервис недоступен, страницы показывают соответствующее пустое состояние или сообщение об ошибке.

## Технологии и архитектура

| Уровень | Технологии и реализация |
| --- | --- |
| Фронтенд | React 18, TypeScript 5, Vite 5, React Router 6 |
| Данные и компоненты | TanStack React Query, Axios, Tailwind CSS, Radix UI, Lucide, React Markdown |
| Анимация | GSAP 3.15, `@gsap/react`; ScrollTrigger / ScrollSmoother загружаются по необходимости для About |
| Бэкенд | Node.js, Express 5, CommonJS; маршруты, бизнес-сервисы и репозитории |
| База данных | MongoDB, Mongoose 8 |
| Аутентификация | Хеширование паролей bcrypt, JWT, проверка аккаунта/администратора в базе и отзыв сеансов через `tokenVersion` |
| ИИ | Общий `DeepSeekAssistant`, SSE, управляемый веб-поиск и извлечение текста статей |
| Изображения и файлы | Multer, Sharp, Tencent Cloud COS / SCF, краткосрочные подписи и загрузка напрямую из браузера |
| Публичные страницы | Реальный HTML главной, About и Privacy генерируется при сборке; интерактивность React сохраняется во время работы |
| Развёртывание | ECS / Nginx / systemd; в репозитории также есть конфигурация Vercel |
| Мобильные устройства | Адаптивный веб-интерфейс, Web App Manifest, конфигурация Capacitor и Android-проект |

```text
Браузер / страницы React
    |
    +-- Разработка: Vite проксирует /api и /uploads
    +-- Продакшен: обратный прокси Nginx / отдельный API origin
            |
            v
        Express API
            +-- Проверка JWT / аккаунта / прав доступа
            +-- Service / Repository -- MongoDB
            +-- DeepSeekAssistant -- DeepSeek
            |        +-- NewsAPI / RSS издателей / управляемое чтение веб-страниц
            +-- Защищённые сервисы хранения -- SCF / COS
                                                 ^
                       Загрузка или скачивание из браузера с временным разрешением
```

Основные модели данных: `User`, `EnrolledUser`, `News`, `Announcement`, `Event`, `ActivityMedia`, `Resource`, `SocialPost`, `Notification`, `Chat`, `AiSettings` и `DailyNewsJob`, а также модели периодов сбора, поданных материалов, загрузок, настроек взносов и подтверждений оплаты. Функции используют существующих пользователей и список группы, не создавая второй набор данных о студентах.

## Быстрый старт

### 1. Подготовьте окружение

- Git, Node.js и npm. Существующее развёртывание на ECS использует **Node.js 22**; рекомендуется та же основная версия локально. Репозиторий не задаёт обязательное ограничение `engines`.
- Доступный экземпляр MongoDB. В существующем развёртывании используется MongoDB 8. Некоторые операции поддерживают standalone MongoDB; транзакции replica set не требуются для запуска.
- ИИ и облачные загрузки — необязательные внешние сервисы. Без настройки эти функции недоступны, но публичные страницы с описанием продукта продолжают работать.

### 2. Клонируйте репозиторий и установите зависимости

```bash
git clone https://github.com/Mason1035/uniclub-main.git
cd uniclub-main
npm ci
npm --prefix uniclub-backend ci
```

Можно также использовать `npm run install-all`: команда запускает `npm install` для фронтенда и бэкенда. Зависимости GSAP берутся из пакетов в `vendor/`; сохраняйте этот каталог при клонировании, сборке и развёртывании.

### 3. Настройте бэкенд

Скопируйте файл примера:

```bash
cp uniclub-backend/.env.example uniclub-backend/.env
```

Windows PowerShell:

```powershell
Copy-Item uniclub-backend/.env.example uniclub-backend/.env
```

Укажите в `uniclub-backend/.env` как минимум:

```dotenv
MONGODB_URI=mongodb://127.0.0.1:27017/uniclub
JWT_SECRET=replace_with_a_long_random_private_secret
PORT=5050
REQUIRE_ENROLLED_ROSTER=true
ALLOWED_EMAIL_DOMAINS=
```

Строка подключения приведена для локального примера; замените `JWT_SECRET`. Значения-заглушки NewsAPI / Gemini в примере не являются действующими ключами. Очистите их, если соответствующие сервисы не используются. Настройка текущего DeepSeek описана ниже и не требует ключа Gemini.

Если `mongod` уже установлен, запустите его в отдельном терминале:

```bash
npm run mongo
```

По умолчанию скрипт слушает `127.0.0.1:27017` и хранит данные в `~/data/db`; он не устанавливает MongoDB. Если сервис базы уже работает, повторный запуск не нужен. `MONGOD_BIN`, `MONGODB_DBPATH` и `MONGODB_PORT` позволяют изменить локальный исполняемый файл, каталог данных или порт.

### 4. Запустите фронтенд и бэкенд

```bash
npm start
```

| Сервис | Адрес по умолчанию |
| --- | --- |
| Фронтенд | <http://localhost:8081> |
| Проверка состояния бэкенда | <http://localhost:5050/api/health> |
| О проекте | <http://localhost:8081/about> |
| Вход / Панель управления | <http://localhost:8081/auth> / <http://localhost:8081/admin> |

Бэкенд начинает слушать порт только после подключения к базе данных. При первом использовании [создайте администратора и список группы](#accounts). Публичная главная страница не создаёт участников или рабочий контент автоматически.

Можно запускать `npm run backend` и `npm run frontend` в отдельных терминалах. Стандартные команды запуска работают в Windows. Старые скрипты `start:win` / `stop:win` всё ещё предполагают порт 5000 и завершают процессы на портах, поэтому не рекомендуются как основной способ запуска.

## Окружение и внешние сервисы

### Где находится конфигурация

| Настройка | Место и назначение |
| --- | --- |
| Подключения бэкенда, аутентификация и серверные секреты | `uniclub-backend/.env` или защищённые переменные окружения на сервере |
| Прокси фронтенда для разработки | `VITE_API_PROXY_TARGET` в корневом `.env.local`; по умолчанию `http://localhost:5050` |
| API URL фронтенда в продакшене | `VITE_API_URL` при сборке; можно оставить пустым при обратном прокси на том же origin или указать origin отдельного API, не добавляя `/api` повторно |
| API-ключ DeepSeek | Настраивается в `/admin/ai` и хранится зашифрованным в `AiSettings` |
| Настройки хранения | Настройки хранилища материалов в панели управления; записываются в приватный файл конфигурации, путь можно изменить через `QUANTIFICATION_STORAGE_CONFIG_PATH` |

**Переменные `VITE_*` попадают в браузерную сборку и не должны содержать секреты.** Старый корневой `.env.example` содержит `VITE_API_URL=http://localhost:5000`. Это не текущий порт прокси для разработки; не копируйте его без изменений в конфигурацию продакшена.

При изменении порта бэкенда перед запуском задайте цель прокси в корневом `.env.local`:

```dotenv
VITE_API_PROXY_TARGET=http://localhost:5051
```

Корневой скрипт запуска выбирает порт бэкенда на основе этого адреса. Если дополнительно задан `PORT`, значения должны совпадать. После изменения `VITE_API_URL` для продакшена нужно пересобрать фронтенд.

### Необязательные сервисы

| Сервис | Настройка | Без настройки |
| --- | --- | --- |
| DeepSeek | Создайте `AI_SECRET_ENCRYPTION_KEY`, перезапустите бэкенд, сохраните API-ключ и проверьте соединение в панели управления | ИИ администратора, вопросы к новостям и ежедневная генерация недоступны |
| Поиск новостей | Существующий `NEWS_API_KEY`; общий слой поиска также может использовать RSS выбранных издателей | RSS может дополнить результаты с учётом ограничений источников, свежести и сети |
| Прямой адаптер COS | `OBJECT_STORAGE_PROVIDER=cos`, `COS_BUCKET`, `COS_REGION`, `COS_SECRET_ID`, `COS_SECRET_KEY` | Реальная загрузка материалов недоступна |
| SCF + COS | Приватный бакет, регион, URL вызова функций, соответствующая серверная аутентификация и настройки хранилища в панели | Соответствующие облачные загрузки/скачивания недоступны |
| Медиа мероприятий | Защищённый SCF, `CLASSHUB_SCF_AUTH_SECRET`, права только на префикс мероприятий и CORS | Оригиналы изображений и миниатюры не могут корректно сохраняться |
| Источники запросов в продакшене | `CORS_ORIGINS` и `BACKEND_URL` для реальных доменов | Междоменные запросы или создаваемые ссылки могут не работать |
| Cron с аутентификацией | `CRON_SECRET` | Внешние запросы Cron отклоняются |

Для хранения также нужны облачные ресурсы, политики приватного доступа, CORS и постоянные каталоги. `npm start` не создаёт бакеты, функции или роли Tencent Cloud. Текущая реализация поддерживает COS; готового адаптера OSS нет. Мероприятия и оценочные материалы используют общую конфигурацию хранилища, но разные префиксы объектов и бизнес-права.

См. [руководство по материалам](docs/quantification.md), [настройку SCF](uniclub-backend/cloud-functions/quantification/README.md) и [COS для мероприятий](docs/activity-v2/ACTIVITY_V2_COS.md). Документы содержат и исторические записи реализации; актуальные настройки определяйте по текущему коду и целевой среде.

<a id="accounts"></a>

## Администраторы и список группы

### Создание администратора

Задайте `ADMIN_EMAIL` и `ADMIN_PASSWORD` в приватном окружении бэкенда, при необходимости также `ADMIN_NAME` и `ADMIN_UNIQUE_ID`, затем выполните из корня репозитория:

```bash
npm run admin:create
```

- Вход выполняется по **номеру студента / идентификатору аккаунта `uniqueId`**, а не по email. Идентификатор отдельного администратора по умолчанию имеет формат `ADMIN-...`.
- При совпадении с существующим аккаунтом скрипт может назначить ему права администратора. Старый пароль сохраняется, если явно не задано `ADMIN_UPDATE_PASSWORD=true`.
- После инициализации удалите эти переменные из постоянного окружения. Не помещайте настоящие пароли в README, примеры команд или Git.
- Для смены пароля существующего администратора используйте команду со скрытым вводом пароля: `npm run admin:password -- admin@example.com`. Email здесь приведён как пример. После смены пароля старые сеансы становятся недействительными.

### Импорт списка группы

Поддерживаются CSV, TSV и JSON. Номер студента и имя обязательны; email необязателен. Пример CSV с вымышленными участниками:

```csv
uniqueId,name
202500001,Example Member A
202500002,Example Member B
```

Сначала проверьте импорт, затем запишите данные:

```bash
npm run roster:import -- ./roster.csv --dry-run
npm run roster:import -- ./roster.csv
```

`--dry-run` не изменяет аккаунты, список или индексы. Реальный импорт создаёт отсутствующие аккаунты для входа. **Начальный пароль совпадает с номером студента и должен быть изменён при первом входе.** Повторный импорт сохраняет существующие пароли, роли и профили. Не добавляйте настоящий список группы в публичный репозиторий.

По умолчанию регистрация требует совпадения email и номера студента со списком. Основной текущий сценарий — импорт аккаунтов и вход непосредственно по номеру студента. `REQUIRE_ENROLLED_ROSTER=false` отключает проверку списка при регистрации; это не обычный способ исправления ошибочных данных списка.

Случайный выбор использует пересечение `User.isEnrolled` и `EnrolledUser.uniqueId`, без исключения по роли администратора. Студенты-администраторы из списка участвуют; отдельные администраторы вне списка — нет. Каждый выбор использует полный набор участников, поэтому один человек может выпасть несколько раз подряд. Браузерный `crypto.getRandomValues()` с rejection sampling предотвращает смещение от операции по модулю.

<a id="ai"></a>

## ИИ и ежедневные новости

### Общий сервис ИИ

Помощник администратора, вопросы к новостям и ежедневные новости используют общий `DeepSeekAssistant`, настройки базы и ключ. Отдельные ключи или клиенты ИИ для этих функций не создаются. Текущий код использует `deepseek-flash` и `https://api.deepseek.com`; выбор модели сосредоточен в общем сервисе.

Создайте основной ключ шифрования:

```bash
npm --prefix uniclub-backend run ai:init-secret
```

Перезапустите бэкенд, введите API-ключ DeepSeek в `/admin/ai` и проверьте подключение. Основной ключ — это значение из 32 байтов, закодированное в Base64; API-ключ хранится с шифрованием AES-256-GCM. Сохраняйте в резервной копии и базу данных, и основной ключ. Если ключ потерян или заменён, сохранённый API-ключ нельзя расшифровать и его нужно ввести снова.

### Помощник администратора по контенту

Поддерживаются текст и изображения, 12 сценариев, потоковая генерация, Markdown, последующие правки и остановка генерации. **Описания ресурсов, черновики объявлений, новостные статьи и тексты мероприятий** имеют предпросмотр публикации в соответствующем разделе. После редактирования, проверки и подтверждения контент публикуется через исходные бизнес-API. Генерация сама по себе не публикует материал.

### Вопросы к новостям

- Фронтенд отправляет только ID статьи и вопрос. `GET/POST /api/chat/:articleId` на сервере читает доверенный текст статьи, её видимость и историю текущего пользователя.
- Краткое содержание, взгляды автора и извлечение организаций прежде всего опираются на статью. Вопросы «почему», анализ последствий и сравнения могут включать reasoning.
- Вопросы о последних событиях, текущем состоянии, дальнейших изменениях или явные просьбы поискать информацию при необходимости запускают общий поиск. Внешние страницы считаются недоверенными справочными данными, а не системными инструкциями.
- Для длинных статей и истории диалога установлен бюджет контекста. SSE выводит ответ частями через существующий Markdown-рендерер; внешние источники берутся только из реального поиска.
- При сбое поиска модель может ответить на основе статьи. Диалоги хранятся в существующей модели `Chat` отдельно для каждого пользователя и статьи. Максимальная длина вопроса — 1 000 символов.
- На бэкенде действуют ограничения частоты и защита от одновременных запросов. По умолчанию вопросы к новостям ограничены 20 запросами на пользователя за 10 минут. Сейчас это защита в памяти одного процесса, а не распределённая система квот.

### Ежедневные новости ИИ

Настройки, статус и история заданий доступны в `/admin/ai#daily-news`. По умолчанию запуск происходит в `19:00` по пекинскому времени и создаёт две статьи в день. Количество настраивается от одной до пяти статей. Категории: искусственный интеллект, технологии, программная инженерия, наука и образование.

```text
Проверка по расписанию / запуск с подтверждением администратора
    -> Поиск через NewsAPI + RSS издателей
    -> Проверка свежести, издателя и источника
    -> Выбор темы, чтение источников, генерация и проверка фактов
    -> Подготовка полного пакета
    -> Переключение видимого пакета при успехе; сохранение ручных статей и старых записей
```

Задание использует реальные источники, опубликованные за предыдущие 24 часа. При недостатке надёжных источников или ошибке проверки система не заполняет пробелы выдуманным контентом и не заменяет последний успешный пакет. Старые новости ИИ архивируются по пакетам; статьи, созданные вручную, автоматически не удаляются.

При `NODE_ENV=production` постоянный процесс бэкенда проверяет задания по расписанию. Запуск среды разработки не вызывает платные сервисы ИИ автоматически. Vercel Cron использует защищённый endpoint `/api/cron/daily-news`, требует `CRON_SECRET` и тариф, поддерживающий заданную частоту и достаточное время выполнения.

Для ручной диагностики выполните в каталоге бэкенда:

```bash
cd uniclub-backend
node manual-curation.js --dry-run
```

**Этот `--dry-run` всё равно обращается к сети и платному ИИ; он лишь запрещает сохранение новостей.** Без флага команда пытается опубликовать результат. `--force` явно пересоздаёт пакет за текущий день. Старые команды обработки новостей теперь используют единый ежедневный процесс; не настраивайте их по старым инструкциям Gemini с запуском в полночь по времени Далласа.

Бесплатный тариф NewsAPI Developer предоставляет статьи с задержкой 24 часа и официально предназначен только для разработки и тестирования, исключая staging и production. Для использования этого провайдера в продакшене нужен подходящий тариф. См. [официальные тарифы NewsAPI](https://newsapi.org/pricing). RSS может дополнить источники, но локальный успех не гарантирует работу серверной сети, страниц источников или результатов за любую дату. Подробности реализации — в [документации ежедневных новостей](uniclub-backend/README.daily-news.md). Проверяйте результаты ИИ и ссылки; расходы зависят от провайдера и фактического использования.

## Развёртывание и эксплуатация

### Результат сборки и HTTP-маршруты

`npm run build` создаёт `dist/`, включая:

- `index.html`, `about.html`, `privacy.html`: настоящий контент для посетителей.
- `app.html`: приватная оболочка приложения для входа, страниц участников и панели управления.
- `404.html`: страница неизвестного маршрута.
- `sitemap.xml`, `seo-routes.json`, `static/` и публичные ресурсы.

Не перенаправляйте все неизвестные URL на главную без разбора. Развёртывание должно различать публичные страницы, приватную оболочку, проксирование API и настоящие ответы 404. Canonical URL, директивы robots, JSON-LD и sitemap охватывают только проверенные публичные страницы с описанием продукта.

### ECS / Nginx / systemd

Репозиторий содержит процедуры публикации, резервного копирования и отката для существующего сервера; см. [`deploy/ecs/README.md`](deploy/ecs/README.md). Используются постоянный процесс Node.js, MongoDB и Nginx, что соответствует текущим требованиям файловой конфигурации, загрузок и фоновых заданий.

После проверки доступа по SSH, целевых каталогов и конфигурации окружения сопровождающие могут выполнить:

```bash
bash deploy/ecs/push.sh
```

Команда собирает проект, передаёт файлы и переключает версию на сервере. **Это не универсальный установщик нового сервера одной командой.** Перед запуском проверьте целевой сервер.

При развёртывании учитывайте следующее:

- Храните окружение бэкенда, загрузки и приватную конфигурацию отдельно от каталогов релизов. Включайте их в защищённые резервные копии, а не в Git или браузерный пакет.
- Публичный HTTPS обслуживает Nginx. Бэкенд и база данных должны слушать loopback или внутренние интерфейсы согласно топологии развёртывания.
- Настройте реальные `CORS_ORIGINS` продакшена. `TRUST_PROXY=loopback` предназначен только для соответствующей схемы с локальным обратным прокси.
- Настройте прокси для потоковой передачи SSE с достаточными тайм-аутами. Кеширование или буферизация промежуточных слоёв не должны задерживать вывод ответа по частям.
- После публикации проверьте состояние сервисов, вход, публичный HTML, статические ресурсы, ответы 404 для неизвестных URL и изменённые функции.
- Резервная копия должна включать как минимум MongoDB, загруженные файлы, настройки хранилища и основной ключ ИИ. Откат кода не откатывает базу данных.

### Vercel и мобильные проекты

`vercel.json` содержит настройки сборки, API, публичных страниц, статических ресурсов, 404 и Cron. Загрузки на диск, запись приватной конфигурации, ограничения запросов в памяти и длительные задания ИИ требуют адаптации к платформе. Не предполагается, что все существующие функции можно без изменений перенести в serverless.

В репозитории есть конфигурация Capacitor и Android-проект с историческими идентификаторами `Uniclub`. Адаптивный сайт и Web App Manifest не означают, что приложения Android/iOS опубликованы или что данные группы доступны офлайн.

### Обновление данных

Существующие скрипты охватывают предпочтения питомца по умолчанию, инициализацию взносов, ежедневные новости и Activity V2. Они находятся в `uniclub-backend/migrations/` или скриптах бэкенда. Сначала создайте резервную копию, прочитайте нужный скрипт и документацию модуля, затем решайте, выполнять ли его. Не запускайте весь каталог без проверки.

Миграция Activity V2 по умолчанию работает в dry-run, использует явно заданный `ACTIVITY_MIGRATION_MONGO_URI` и записывает данные только с `--apply`. Для удалённых целей нужен также `--allow-remote`. Взносы инициализируются командой `npm --prefix uniclub-backend run fees:init`; скрипт совместимости ежедневных новостей — `uniclub-backend/migrations/20261006_daily_ai_news.js`. Эти операции отделены от обычной сборки фронтенда.

## Безопасность, конфиденциальность и известные ограничения

| Область | Текущее поведение и границы |
| --- | --- |
| Права доступа | Бэкенд проверяет реальный аккаунт, версию сеанса и статус администратора. Скрытые ссылки, robots и noindex не заменяют авторизацию API или медиа |
| Старые API и медиа | Некоторым старым анонимным endpoint и ссылкам на медиа ещё нужен отдельный аудит. Проект не заявляет о полной приватности всех рабочих данных; см. [аудит SEO/GEO](docs/SEO_GEO_AUDIT.md) |
| Масштаб группы | Одна группа на развёртывание; нет изоляции нескольких организаций, общего университетского управления или переключения групп |
| Взносы | Одна текущая запись на пользователя; скриншоты хранятся в базе, администраторы сверяют поступления вручную. Нет платёжного шлюза, автоматического обнаружения оплаты, OCR, возвратов или учёта нескольких периодов |
| Материалы для оценки | ZIP до 500 MiB, загрузка частями и повторные попытки в сеансе. Проверки на вирусы нет; после обновления страницы при незавершённой загрузке обычно нужно снова выбрать файл. Полное возобновление между загрузками страниц по файловому дескриптору не реализовано |
| Альбомы мероприятий | JPEG / PNG / WebP, до 10 MiB на изображение, с созданием миниатюр WebP. Из миниатюр удаляются метаданные; оригиналы могут сохранять EXIF. Новые медиа используют управляемый доступ по подписи |
| Случайный выбор | Пересечение списка группы и подходящих аккаунтов; записи без созданного аккаунта исключены. Повторы допустимы, режима без повторений нет |
| ИИ | Ключи находятся на сервере. Результаты нужно проверять. Поиск, генерация, квоты и стоимость зависят от внешних сервисов |
| Несколько процессов | Ограничения запросов ИИ пока действуют в памяти процесса; блокировки динамической конфигурации хранилища также ограничены одним процессом. Перед масштабированием нужна отдельная оценка |
| Файлы и резервные копии | Объекты COS, MongoDB и локальные файлы управляются отдельно. Настоящие списки, скриншоты оплаты, ZIP участников, окружение и резервные копии не должны попадать в публичный репозиторий |

Пользователи могут прочитать [описание конфиденциальности и хранения в браузере](https://csrg3b.top/privacy). Исторические отчёты проверки функций не означают, что все проблемы решены в текущем продакшене.

Если проблема связана с аккаунтами, ключами или приватностью участников, не публикуйте детали эксплуатации, реальные данные или учётные сведения в открытом Issue. Сообщите сопровождающим через установленный приватный канал связи; после подтверждения можно опубликовать описание исправления без чувствительных данных. В репозитории пока нет отдельного `SECURITY.md` или гарантированного срока ответа.

## Частые вопросы

### Почему localhost:8081 отклоняет соединение?

Убедитесь, что `npm start` работает, зависимости установлены и порт 8081 свободен. Если бэкенд не запускается, проверьте ошибки MongoDB и окружения в терминале. `ERR_CONNECTION_REFUSED` означает, что на целевом порту нет доступного сервиса; обновление страницы не решит эту проблему.

### Почему запросы API не работают, хотя фронтенд открывается?

Проверьте <http://localhost:5050/api/health>, затем сопоставьте `VITE_API_PROXY_TARGET` с реальным портом бэкенда. Прокси для разработки и `VITE_API_URL` продакшена выполняют разные задачи. Отдельному API-хосту в продакшене также нужен корректный CORS. При отсутствии связи с базой endpoint проверки состояния может вернуть 503.

### Почему на главной нет сообщений группы или не открывается панель управления?

Главная страница для посетителей показывает публичное описание продукта и не читает контент группы. После входа доступная информация зависит от опубликованных записей. Для панели нужны права администратора в базе. Изменение кнопок фронтенда или подделка поля роли не предоставляет этих прав.

### Почему генерация новостей возвращает `SEARCH_NO_RESULTS` или `INSUFFICIENT_SOURCES`?

Проверьте в записях задания результаты поиска, независимых издателей, доступность текста статей и время публикации. Действующий ключ не гарантирует достаточное число надёжных источников. Задержка бесплатного NewsAPI, сбои RSS и серверной сети могут влиять на результат. Система не восполняет нехватку расширением временного окна, отключением проверок или выдуманными новостями.

### Почему ИИ работает локально, но не после развёртывания?

Сравните основной ключ ИИ, настройки базы, сеть поиска, извлечение текста источников, тайм-ауты прокси и длительность заданий в целевой среде. Одинаковые настройки интерфейса не означают одинаковые серверные ключи, сеть и постоянные каталоги. Определяйте сбойный этап по кодам ошибок заданий.

### Почему загрузка сообщает о недоступном хранилище или ошибке CORS?

Проверьте настройки хранилища в панели, приватный бакет, аутентификацию функций, права на нужные префиксы, реальный origin сайта и заголовки запросов. Медиа мероприятий не должны использовать старую незащищённую функцию выдачи credentials. Получайте новую подпись после истечения срока; не делайте бакет публичным для обхода ошибки.

### Почему участник отсутствует в случайном выборе?

Проверьте, что человек есть и в реальном текущем списке группы, и среди подходящих аккаунтов участников. Записи без такого аккаунта не включаются. Роль администратора сама по себе не исключает человека, но отдельный администратор вне списка не считается участником группы для случайного выбора.

### Можно ли сразу обслуживать несколько групп, включить тёмную тему или выпустить мобильное приложение?

Эти продуктовые возможности пока не завершены. Нескольким группам нужна явная схема изоляции данных; текущая тема фиксирована как светлая. Мобильному проекту ещё нужны брендирование, подпись, настройка платформ и соответствующие проверки.
